# 术语表

> 面向非技术读者。文档中每个首次出现的项目专有术语都应登记在此（登记义务见 standards/03）。
> 按拼音/字母排序；解释只用日常语言，不用另一个术语解释术语。

- 状态：草稿
- 日期：2026-11-02

| 术语         | 英文/别名            | 通俗解释                                                                                             |
| ------------ | -------------------- | ---------------------------------------------------------------------------------------------------- |
| ADR          | decision record      | "决策记录"——把一次重大技术选择的背景、决定和理由写成一篇短文，编号保存，只增不改                     |
| Cell         | 执行单元             | 一次 Agent 任务运行的"独立隔舱"：有自己的工具、记忆和上下文；一个舱出问题不沉整船                    |
| Cordis       | —                    | Keel 之前一代的插件框架，存量插件经"Cordis Adapter"迁移到 Keel（历史指代）                           |
| DSH          | —                    | Keel 之前一代的 Agent 运行环境，它踩过的坑成为 Keel 的验收标准（历史指代）                           |
| Keel（龙骨） | —                    | 本项目名：船的龙骨是承载整个船体的底座结构，Keel 是承载 Agent 运行的底座                             |
| Keel Core    | 内核 / 控制面        | Keel 的"驾驶舱"：调度、授权、预算、恢复、账本都归它管，任何插件都不能取代它                          |
| 补偿事务     | compensation         | 出错后"把已做掉的事收尾"的安排：做每件有外部影响的操作前，先写好收尾办法，出错时按依赖顺序执行       |
| 策略 hook    | policy hook          | 给策略插件预留的"受限插话点"：只能建议或否决，不能接管驾驶                                           |
| 插件清单     | manifest             | 插件的"报关单"：装什么能力、要什么权限、出事怎么收尾、跟谁兼容——安装前内核先查验，查验不过就装不进去 |
| 换页         | context paging       | 上下文太长时，把旧内容移出去、需要时再移回来的机制，像书的附录                                       |
| 看板         | board                | 记录每个阶段做到哪了的表格，只在此处维护                                                             |
| 模型网关     | model gateway        | 所有调用大模型的必经关卡：先查权限、扣预算，再放行，最后记账                                         |
| 热装配       | hot assembly         | 换插件的方式：开一个新隔舱装载新版本，而不是在运行中的全局登记表里直接改                             |
| 水密隔舱     | —                    | 龙骨的比喻：船舱互相隔水，一舱进水不沉整船——对应 Cell 的故障隔离                                     |
| 挽具         | Agent Harness        | 套在 Agent 身上的"安全带与缰绳"：工具、上下文、预算、停止条件等运行环境的统称                        |
| 一致点       | consistency point    | 执行账本里"写到这就绝对安全"的标记点；恢复任务时从最近的一个点继续                                   |
| 越界副作用   | out-of-bounds effect | Agent 在自己隔舱外造成的变化（如发邮件、改外部系统的数据），必须事先声明收尾办法                     |
| 执行账本     | ledger               | 只追加、不改写的"航海日志"：每步决策、花销、状态变化都记下，可重放、可审计                           |
| 作用域       | scope                | "谁看得见什么"的边界：工具与记忆按 Agent / 会话分区，互不污染                                        |
