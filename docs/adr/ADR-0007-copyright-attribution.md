# ADR-0007：版权署名落实为 GitHub 用户名

- 状态：定稿
- 日期：2026-11-02
- 关联：[ADR-0006](ADR-0006-mit-license.md)（MIT 与占位署名条款）；roadmap/00（Phase 2 开工）
- 取代：无——本篇是**落实** ADR-0006 决策 2 的"占位可随时改为个人/组织署名"，不推翻许可证选择

## 背景

MIT 落盘时版权主体用占位串 "Keel Project Contributors"，Phase 0 与 Phase 1 收官各挂过一次待决。现在仓库已启用远端（私有 GitHub 仓库），且 Phase 2（Cordis 兼容层）开工——发布物、贡献记录与 README 需要一致署名，继续留占位会让后续每一次署名变更都变成历史文本修订。

## 决策

1. 版权主体定为 **"qingbird1983"**（项目所有者的 GitHub 用户名，作为公开标识）。
2. `LICENSE` 的版权行与两份根 README 的许可证行同步替换为 `© 2026 qingbird1983`。
3. 年度沿用 2026（MIT 的年度是版权成立年，不随阶段递增）。
4. 将来若迁到组织仓库或需要法定主体署名，**另立 ADR** 记录变更，本篇不回改（ADR 只增不改）。

## 理由

- 单人维护阶段，个人标识最准确；"Contributors" 复数式占位反而暗示存在多方贡献，与实际不符。
- GitHub 用户名是可解析、可追溯的公开标识，无需在仓库里写入真实姓名或邮箱（standards/06 个人数据红线）。
- MIT 允许任意版权主体表述；改署名不影响已分发副本的效力，也没有兼容性代价。

## 后果

- 积极： LICENSE / README / ADR 三处一致，收官清单里的最后一个待决项关闭。
- 代价/风险：用户名不是法律姓名——若将来需要接受外部实质贡献（贡献者授权、 CLA、双许可谈判）或以组织名义主张版权，需换成法定主体并另立 ADR。
- 重评条件：转为组织仓库 / 出现外部贡献者 / 需要法律主体签署的场景。
