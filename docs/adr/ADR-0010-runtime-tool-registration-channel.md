# ADR-0010：运行期工具注册通道（两个 Cell→Core op）与 `tool.provide` 语义扩展

- 状态：定稿（2026-11-03 所有者授权，见切片①设计稿 §10 第 1 项）
- 日期：2026-11-03
- 关联：切片①设计稿 [phase-2/02](../design/phase-2/02-adapter-skeleton.md) §4/§5；契约 [§3.3 可见面矩阵 / §4.6 上下文管理器](../design/phase-1/01-core-api-contract.md)；manifest 稿 [§5.2 能力词表](../design/phase-1/03-plugin-manifest.md)；迁移边界 [01 稿](../design/phase-2/01-cordis-migration-boundary.md) #1/#2；[ADR-0001](ADR-0001-implementation-stack.md)（接口即围栏的选型动机）
- 取代：无——本篇**扩展** `tool.provide` 的运行期语义并补两个通道 op，不新增词表项、不改不变量 I1/I4/I5

## 背景

Phase 2 合同把"旧插件一行不改迁入"定为验收场景 B1（一票否决），边界表 #1 承诺的等价物是"按 scope 注册 + Cell 私有执行表"。切片①设计稿核对代码后发现这条承诺**当前无处落地**：

1. Core 的可见工具表（`ContextManager` 的 scope 分区）在正式接线上**从未由插件填充**——只有测试 rig 与宿主侧适配原型手工 `registerTool()`；真实 run 里 `tool.discover` 返回空表，脚本 driver 直接点名工具执行；
2. 适配原型 `createCordisCtx({ctx, ref})` 在**宿主进程**里构造旧 ctx，只覆盖可见性一半：它既没有 handler，也碰不到 Cell 的私有执行表；
3. 于是"旧插件在自己舱里调用旧 API 注册工具"这条路径**不存在**，B1 无法真实执行，"会话间工具表互不可见"也只能由测试自建数据支撑。

同时有一条硬约束：能力词表是**封闭**的（C-D1），任何变动须 ADR；且跨通道的写入口必须默认拒绝（I4），否则等于给不受信进程开一个无裁决的内核状态写口。

## 决策

1. **新增两个 Cell→Core op**：`tool.register{name, schema}` 与 `tool.remove{name}`，加入契约 §3.3 的 Cell 可见行与 §4.6 的接口表。二者**只携带名字与 schema，不携带 handler**——handler 永远留在 Cell 私有执行表内（内核只认工具名）。
2. **`tool.provide` 语义扩展**（不新增词表项）：从"向本 Cell 私有工具表提供工具（工具清单在代码内）"扩为"同一能力亦可在运行期注册/撤名"；`allow` 限定符从可选变为**可用于收窄可注册的工具名**（缺省 = `*`，与"清单在代码内"不矛盾）。
3. **两半提交的次序 = 执行表先、可见表后，失败回滚执行表**。反向（先写内核）会留下"可见但不可执行"的工具名——决策能选中它、执行必失败，属禁止的静默形态；本地-first 的失败窗口是"可执行但不可见"，同一次调用内即回滚。崩溃窗口（写过内核后进程猝死）由 Cell↔Run 一一对应兜住：该 run 以 `RUN_FAILED{CELL/CRASH}` 收束，不产生跨会话空壳。
4. **版本号由内核侧指派**，Cell 只提交 `{name, schema}`，返回真实 `schemaVersion`。插件/承接层**不得自算版本**——自算就必须在本地记一张表，那正是把旧框架全局注册表搬进 Keel 的形态（原型稿 §5 第 2 条的延续）。
5. **生效时刻 = 下一轮**：注册写 scope 挂起变更日志，由调度器在轮边界取走并写 `TOOL_SCHEMA_CHANGED`（沿用 V1 的按 scope 传播，不新增事件类型）。
6. **授权门禁**：新增 `@keel/host` 的 `permission-rules`，把 manifest 声明编译成授权规则（`tool.provide` → `tool.register`/`tool.remove` 两条），op handler 内先 `auth.check` 再动状态——拒绝即 `AUTH_DENIED` 落账（留痕可查），且不写任何一半状态。词表项若无对应运行期 op（`memory.backend`）**不产出规则**：声明不等于能力。完整的"从运行观察合成声明"仍留切片②，本片只编译**已声明**内容。
7. **承接层的旧 API 面改为异步**（`Promise` 返回），拒绝"同步返回 + 本地排队 + 后台 flush"。
8. **入口切换由宿主承担**：`CellSupervisor.spawnCell` 增加可选 `cellEntry` 覆盖（缺省仍为 `@keel/cell-runtime` 入口），bootstrap 载荷形状不变；旧 ctx 在 Cell 进程内由承接层自带入口构造，作用域由通道绑定盖章、Cell 不可自报。

## 被否方案

| 方案                                        | 否掉的理由                                                                     |
| ------------------------------------------- | ------------------------------------------------------------------------------ |
| 宿主进程代插件注册（原型现状扩到全量）      | handler 在插件进程、注册在宿主 → 名字可见而不可执行；且宿主持有插件语义，破 I1 |
| 同步返回 + 后台 flush                       | 版本必须本地自算（违反决策 4）+ flush 失败发生在插件看不见的时刻 = 静默降级    |
| 旧 ctx 面内置进 `cell-runtime`              | 兼容面塞进内核执行单元 = 病灶进内核；cell-runtime 保持零依赖与新生态形状       |
| 新 op 不走 `auth.check`，仅靠绑定限定作用域 | 只保证"写不到别人的分区"，不保证"未声明者不能写"（I4 默认拒绝失守）            |
| 为每类插件各建一个 `CellSupervisor`         | 为一个路径参数复制整套生命周期管理，是意外复杂度而非隔离边界                   |

## 后果

- 积极：B1 有了真实可执行的链路（可见性与可执行性由同一次调用打通）；"会话间互不可见"由插件自身的注册行为证明，而非测试造数；封闭能力词表第一次真正参与运行期裁决。
- 代价：Cell→Core 多两个 op 与一次往返（承接层开销由 B8 基准测量，不设阈值）；`tool.provide` 的文档语义要读注记才完整；异步化使边界表 #1 出现一处真实让步（返回值同步消费降为 C 档一行 `await`，已按 §10 第 2 项补注）。
- 重评条件：若真样本出现"注册必须同步拿到版本号才能继续"的普遍写法，再评估**内核侧同步视图**方案（例如把版本随 `context.alloc` 预分配给 Cell 的区间）；若出现跨 run 复用工具表的需求（当前恢复语义 = 新 run 重注册），须另立 ADR 讨论分区持久化。
