# ADR-0002：MVP 采用单机部署形态

- 状态：定稿
- 日期：2026-11-02
- 关联：briefs/Keel-Design-V0.1.md（本地简报）；ADR-0001；ADR-0004
- 取代：无

## 背景

部署形态决定接口超时基线、账本分片需求与调度语义。设计简报的验收用例（20 个会话并发、动态增删工具、崩溃隔离、账本恢复）全部可在单机验证；Day-1 分布式会把一致性、超时、部署复杂度前置，且当前没有任何验收用例回 收这部分成本。

## 决策

1. MVP 仅支持单机：Keel Core、Host Layer 与全部 Cell 运行于同一主机，Cell 间进程级隔离（隔离级别细化见 ADR-0005）。
2. 所有跨边界接口（Core↔Cell、Core↔账本）按**可远程化**设计：显式超时参数、幂等可重试语义、稳定错误码、消息可序列化——但 MVP 不实现网络传输，本机 IPC/stdio 即可。
3. 账本存储为本地 append-only 分段文件；存储后端走接口抽象，为未来嵌入式库或远程存储留缝。

## 理由

- 单机覆盖全部 MVP 验收用例，复杂度最小。
- "Day-1 分布式"否决理由：无对应验收用例，纯成本前置；分布式一致性需求应待真实瓶颈实证后再设计。

## 后果

- 积极：MVP 复杂度显著下降；账本无跨机共识问题（单写者）。
- 代价：跨机扩展需后续 ADR + 传输层实现；本机 IPC 测得的延迟数字不可外推为网络数字（Phase 2+ 需重测超时基线）。
- 重评条件：出现单机容量/可用性的实证瓶颈，或 Cell 需要跨机调度时，新 ADR 立项。
