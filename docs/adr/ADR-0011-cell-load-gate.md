# ADR-0011：Cell 装载门与就绪凭据（插件装载完成前不受理调用）

- 状态：定稿（2026-11-03 所有者授权，见切片②设计稿 [phase-2/03](../design/phase-2/03-manifest-synthesis.md) §10 第 1 项）
- 日期：2026-11-03
- 关联：切片②设计稿 §6（本 ADR 的三条候选与取舍）；切片①设计稿 [phase-2/02](../design/phase-2/02-adapter-skeleton.md) §12 第 5 条（本片收口的限制）；契约 [§3.1 通道 / §7 超时表](../design/phase-1/01-core-api-contract.md)；[ADR-0005](ADR-0005-cell-isolation.md)（进程级隔离与冷启动量级）；[ADR-0010](ADR-0010-runtime-tool-registration-channel.md)（运行期注册通道）
- 取代：无——本篇**收紧 Cell 的应答时机**并给"就绪"一个可查询凭据，不新增 op、不启用事件帧、不改生命周期阶段语义

## 背景

切片① 施工时撞到一个纯时序问题（02 稿 §12 第 5 条已登记）：调度轮次是亚毫秒的，而 Cell 进程从 `spawn` 到插件装载完成要上百毫秒（ADR-0005 的进程级后端代价）。于是"起 run"与"插件已装载"之间**没有任何契约级凭据**——当时只能在测试侧自己等（用分区里出现注册名字、或一次 `tool.exec` 得到应答作观察）。

这不是测试专属问题：生产上如果宿主在装配之后立刻起 run，旧插件的第一轮决策会拿到**空工具表**——插件确实装载成功了，但那一轮看不见它。三条候选：新增 `cell.activated` 报到 op（内核要多认识一件没有裁决语义的事）；启用 §3.1 已定义但 MVP 无推送方的事件帧（要把"账本事件按订阅分发"的语义重新解释成生命周期信号，并定义接收方义务）；或者让舱在装载完成前**不受理调用**，宿主用一次既有查询确认就绪。

## 决策

1. **装载门落在 `startCell`**：`CellHandle` 增加 `markReady()`；门未开时对端请求**排队不应答**（帧照常读取，不丢不报错）。默认入口在装载末尾调用（与现状行为等价），承接层入口在 `await activate(ctx)` 之后调用——旧 ctx 的注册调用因此一定先于第一次应答进入内核分区。
2. **就绪凭据 = 一次 `cell.snapshot` 应答**（契约既有 Host→Cell op，不新增接口）。宿主侧新增收敛点 `wireCell()`（`spawn → serve → alloc → 就绪探测`），装配、热升级、起 run 三条路共用同一个就绪事实。
3. **探测超时即拒绝装配**：超时口径进契约 §7 超时表；探测失败（超时或通道断）→ 宿主 `dispose` 该 Cell（退出分类 = `killed`）并明确拒绝装配，**不静默重试到成功为止**。activation 抛异常的旧代码路径不悬挂：承接层入口的崩溃语义（非零退出）会关闭通道，在途请求按既有帧规则以 `TRANSPORT/BADFRAME` 回落。
4. **不动的东西写明白**：Supervisor 的生命周期阶段（`creating/ready/running/…`）语义不变——阶段描述进程与通道，不描述插件装载；bootstrap 载荷形状不变；不新增 op；事件帧继续无推送方。

## 被否方案

| 方案                               | 否掉的理由                                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------------------------ |
| 新增 Cell→Core op `cell.activated` | 可见面矩阵再加一个没有裁决语义的纯信号；矩阵是"插件能请求什么"的围栏，报到不属于任何裁决         |
| 启用事件帧 `ev:"CELL_ACTIVATED"`   | §3.1 的事件类定义是"账本事件按订阅分发"，挪用为生命周期信号 = 重新解释契约，还要新定义接收方义务 |
| 保留"测试侧自己等"，产品不做就绪   | 旧插件首轮决策拿到空表是真实行为，B2/B6 的"装配后可用"不能靠测试兜；限制留着等于把债写进产品     |
| 固定 sleep 后再起 run              | 慢机器随机红、快机器白等；且没有把"就绪"表达成任何可查询事实                                     |

## 后果

- 积极：装配/升级/起 run 共享一个可查询的就绪凭据；旧插件的第一轮决策不再可能看见空表；承接层与内核之间的时序假设从测试细节升为契约级行为。
- 代价：Cell 的应答时机改变（装载期请求会排队），需在契约 §3.1/§7 各补一条注记；宿主多一次往返（就绪探测，开销由 B8 基准观察，不设阈值）；`markReady()` 成为入口的义务——漏调会让舱永远不应答，因此**默认入口也显式调用**，让遗漏在测试里立刻表现为超时而不是偶发空表。
- 重评条件：容器/microVM 后端启用后冷启动量级变化（就绪超时需按后端配置，见 ADR-0002/0005）；若出现"分阶段装载"的真实插件（activation 之后仍有异步注册），单次就绪探测不足以表达"全部装载完"，须另立 ADR 讨论多阶段就绪或注册完成清单。
