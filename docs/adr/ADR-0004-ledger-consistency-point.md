# ADR-0004：执行账本采用轮边界一致性点

- 状态：定稿
- 日期：2026-11-02
- 关联：briefs/Keel-Design-V0.1.md（本地简报）§6.3；ADR-0002；ADR-0005（待写）
- 取代：无

## 背景

"状态不可丢失"与账本吞吐需要折中。逐事件同步 fsync 最安全，但多会话高并发下吞吐损失大；纯异步落盘崩溃丢尾部，恢复粒度不可控。Agent Run 天然以**调度轮**为决策单位（每轮 = 一次决策 + 若干工具调用），是恢复的最小有意义粒度。

## 决策

1. 账本事件在轮内**异步追加**（缓冲写入，不逐条 fsync）。
2. 每个调度轮的决策边界强制 flush + fsync，该边界即**一致点（consistency point）**，以显式 `CHECKPOINT` 事件写入账本。
3. 恢复语义：Agent Run 从最近一致点恢复；一致点之前的轮完整可信，之后的事件可能缺失。
4. 半轮内已发生的越界副作用不靠"重放屏蔽"兜底，由**补偿事务**（Phase 0 D 任务）声明覆盖——恢复流程必须先核对未决副作用补偿表再续跑。
5. 账本写入失败 = 本轮 fail-stop（该 Cell 本轮失败走故障语义），禁止静默降级为"先跑后补记"。

## 理由

- 逐事件同步：吞吐代价确定但收益有限（轮内事件在崩溃后本就要重做），否决。
- 纯异步：恢复粒度不可控，与"从任意一致点恢复"语义冲突，否决。
- 轮边界：与 Agent 决策原子粒度吻合，CHECKPOINT 事件让重放可自校验。

## 后果

- 积极：吞吐可控；恢复语义清晰；账本单写者（ADR-0002）下实现简单。
- 代价：崩溃最多丢"半轮"事件，其间副作用由补偿兜底——**补偿覆盖面因此成为硬要求**（D 任务验收）；fsync 频率 = 轮频率，Phase 1 基准必须测量。
- 重评条件：轮频率过高或基准不达标 → 允许有界的 N 轮合并 checkpoint（明确的最大丢帧窗口），走规范级修订。
