# ADR-0009：异步资源释放必须等待完成（规范 04 §3 补条）

- 状态：定稿
- 日期：2026-11-03
- 关联：[standards/04 §3](../standards/04-coding.md)（并发与资源，本篇为其补条）；[standards/05 §5](../standards/05-testing.md)（门禁在干净环境可复现）；[standards/09](../standards/09-standards-review.md)（规则级变更须 ADR）；[ADR-0004](ADR-0004-ledger-consistency-point.md)（账本 fail-stop 语义）；[Phase 2 切片①设计稿](../design/phase-2/02-adapter-skeleton.md)（本篇缺陷在该轮收尾核对中发现）
- 取代：无——本篇把既有"确定性释放路径"要求细化到"释放是异步承诺时必须 await"，不推翻原条

## 背景

Phase 2 切片①文档轮收尾时执行"`pnpm clean` 起跑全链"的例行核对，测试门禁第一次出现**极具迷惑性的红**：226 项断言全部通过，`pnpm test` 退出码却是 1，原因是 vitest 捕获到一条未捕获异常——`A FileHandle object was closed during garbage collection ... Please close FileHandle objects explicitly`，且**只在部分机器上、部分时候出现**。

追下去是两个同源的口子：

1. 生产代码 `Ledger.rollSegment()` 写的是 `(await w.opening).close()`——关闭承诺没有被 await，句柄对象的引用在真正关闭前就被丢弃，关闭时机交给了垃圾回收器；
2. 测试 rig 里绕开登记器手工 `new Ledger(...)` 的写入实例从不 close——当前段句柄一直开着，实例被回收时走同一条路。

Node 把"GC 期间关闭 FileHandle"从告警升级为**硬错误**（24+）；CI 锁在 Node 22，只会静默，因此这个缺陷在 CI 上永远不可能被发现。原有条款"一切占用资源的对象必须有确定性的释放路径"已经存在，但**没有堵住"释放动作本身是异步承诺"这一形态**——写了 `close()` 却没等它完成，字面上仍然"有释放路径"。

## 决策

1. **规范 04 §3 补一条硬约束**：释放动作返回 Promise 时（`FileHandle.close()`、`channel.end()`、子进程回收等）**必须 await**；在串行队列/临界路径内的关闭，await 不改变时序语义，只把"何时真的放掉资源"变成可证明的事实。
2. **释放失败按该组件自身的失败语义处理**，不得静默：账本 = fail-stop 锁存（沿用 ADR-0004 与契约 §4.4 写路径纪律），其他组件按各自既定错误路径。
3. **测试 rig 同等适用**：每个会打开资源的实例必须登记到统一的收尾钩子（本项目形态 = `newLedger()` 登记 + `afterEach` 关闭），禁止绕开登记器手搓实例。
4. **门禁环境覆盖差**：CI 运行环境从单一 Node 版本改为矩阵 `[22, 26]`（下限 = `engines` 承诺，上限 = 开发机同 major），`fail-fast: false`；"只在新 runtime 现形"的缺陷要在门禁上可见，而不是靠某台机器偶发。
5. **这类缺陷的回归测试写法**（沉淀为可复用手法）：断言"某事被 await 过"= 包装被观察的方法让完成标志只在真实完成后置位，再断言上层承诺 resolve 时标志已置位；此口径与环境无关，可红可绿已被实证（改回旧写法必红）。

## 后果

- 积极：`Errors 1 error` 这一类"检查全过但命令失败"的红灯从源头消失；资源释放时机成为可断言的事实而非运行时运气；CI 不再在下限版本上替我们沉默。
- 代价：串行队列内多一次 await；实测开销不可测——修复后重采 A8 基准（win32/x64，node v26.13.0）：B1 账本吞吐 24543 events/s、B1b 一致点 0.79 ms/次，与 Phase 1 复采值（24548 / 0.84 ms）同量级（段滚动在默认段阈值下不经该路径，口径不变）。CI 双版本作业使流水线时长翻倍（约 1 分钟量级，可接受）。
- 重评条件：若项目 `engines` 下限上调（例如统一要求 Node ≥24），矩阵相应收敛为单版本；若再出现"仅新版本现形"的缺陷类别，考虑把 CI 矩阵升级为 `[下限, LTS, latest]` 三档。
