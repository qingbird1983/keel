# ADR-0020：Workspace 能力的错误码

- 状态：接受
- 日期：2026-11-03
- 关联：[ADR-0018](ADR-0018-effect-receipts-and-workspace.md)；[契约 §6](../design/phase-1/01-core-api-contract.md)

## 背景

ADR-0018 引入受治理 `workspace.write` 后，出现三类既有错误码无法诚实表达的失败：

- `create` 的目标已存在（独占创建失败）；
- 路径被拒绝（相对路径、`..` 逃逸、符号链接逃逸、非常规文件）；
- 文件系统 IO 失败（父目录不存在、权限、写盘错误）。

复用 `AUTH/DENIED` 会让“授权拒绝”与“路径/文件问题”混在一起，归因失真；复用 `TRANSPORT/BADFRAME` 会把业务失败误报成帧层坏用法。契约 §6 是封闭集合，扩展必须走 ADR。

## 决策

在契约 §6 增加 `WORKSPACE` 域的三个码：

| 码                 | 语义                                                                        | 可重试                       |
| ------------------ | --------------------------------------------------------------------------- | ---------------------------- |
| `WORKSPACE/EXISTS` | `create` 的目标已存在（独占创建语义）                                       | 否（改路径或显式 overwrite） |
| `WORKSPACE/PATH`   | 路径被拒绝：相对路径、`..`/符号链接逃逸、目标不是普通文件、与声明目标不一致 | 否（改路径/声明）            |
| `WORKSPACE/IO`     | 文件系统操作失败（父目录缺失、权限、写盘/读取错误）                         | 视底层错误；默认否           |

- 授权边界仍先走 `auth.check`：不在 `fs.write.allow` 内的路径 → `AUTH/DENIED`（既有码，必留痕）。
- 路径归一/符号链接/目标类型问题 → `WORKSPACE/PATH`；`create` 已存在 → `WORKSPACE/EXISTS`；实际 IO 失败 → `WORKSPACE/IO`。
- 三个码只用于 `workspace.write`（及未来同一能力的读写动作），不改既有码语义。

## 备选与否决

- **复用 `AUTH/DENIED`**：归因失真，且会写出“授权拒绝”账本而实际是路径问题；否决。
- **复用 `TRANSPORT/BADFRAME`**：把业务失败伪装成协议错误；否决。
- **只放 `detail.reason` 不加码**：调用方无法稳定分支，审计只能读字符串；否决。

## 后果

- 契约 §6 与 `ERROR_CODES` 增加三项；文档、测试与 CHANGELOG 同步。
- `workspace.write` 的错误现在可稳定区分“没权限 / 路径不对 / 已存在 / IO 失败”。
- 不新增事件类型、不新增超时数；错误码仍按契约封闭集合管理，后续扩展继续走 ADR。
