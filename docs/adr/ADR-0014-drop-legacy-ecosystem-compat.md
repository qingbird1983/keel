# ADR-0014：放弃全面兼容 DSH/Cordis 旧生态，Phase 2 提前收口，兼容层转归档

- 状态：**已采纳**（2026-11-03 所有者决定；本 ADR 记录决定的边界与后果，不记录实施细节）
- 日期：2026-11-03
- 关联：[phase-2 合同](../roadmap/phase-2-cordis-compat.md)（本 ADR 使其提前终止）；[design/phase-2/08 真样本观察记录](../design/phase-2/08-real-sample-observation.md)（触发材料）；[design/phase-2/01 边界表](../design/phase-2/01-cordis-migration-boundary.md)（停止回填）；[design/phase-3/01 反面教材清单](../design/phase-3/01-legacy-anti-patterns.md)（本决定的产出之一）；[architecture/01 §7](../architecture/01-keel-overview.md)；ADR-0001/0002/0006/0007 与 ADR-0010~0013（**均不撤回**，理由见"后果"）

## 背景

Phase 2 的目标是"承接 Cordis 存量插件全量语义"，六片切分中前五片已完成（B1/B2/B3/B4/B6/B7 达成，431 项测试全绿）。切片⑥ 的第一批真样本是三枚**真实发布的第三方插件**，结果（08 稿）：

1. 三枚没有一枚走到 ctx 兼容面——两枚死在入口形状识别，一枚死在它按 npm 名 import 宿主包；
2. 一手来源核对显示旧框架的插件形态**还在继续演变**（当前主形 `apply(ctx, config)`；我们按上一世代形状建的承接面与边界表已经过时）；
3. 真样本普遍在用的面（往系统提示里塞段落、工具宣布本轮结束、运行中向用户申请更宽权限、跨插件扩展点注册表）恰恰是 Keel 三条不变量（I1 插件不接管控制流、I2 能力显式声明、I4 默认拒绝）明确不允许的形态；
4. 我们花最大力气防的旧写法（插件自带模型 key、跨插件共享可变状态、事件总线）在三枚里出现 0 次。

由此，所有者给出三条理由并作出决定：**旧生态形态未定、跟不完；Keel 定位是"少而精"的需求驱动定制底座，不是旧插件收容所；真样本暴露的野路子与内核不变量正面冲突。**

## 决策

1. **停止全面兼容旧生态**：边界表 01 稿**冻结**——不再新增行、不再改判、08 稿候选行 #16~#26 **不回填**（原样转为反面教材）。B5【一票否决】"真样本复跑 + 符号闭环"义务**作废，不追补**。
2. **Phase 2 提前收口**：不继续切片⑥ 的兼容范围。已达成项按原样保留为历史证据；未完成项（B1 真样本复跑、B5）标注"随本决定作废"，不表述为通过。`phase-2.end` tag 是否打、打什么名，**归所有者**。
3. **`@keel/cordis-adapter` 从主开发线剥离，标记为归档/实验性**：包与全部代码、测试**保留在仓库内不删除**；README 与 package.json 标 `archived`；不再接受新兼容面开发；内核任何能力不以它为依赖前提。
4. **进入 Phase 3：原生插件生态**，按需求驱动产出第一批"少而精"的**标杆原生 manifest 插件**；Phase 3 的范围合同见 [roadmap/phase-3-native-ecosystem.md](../roadmap/phase-3-native-ecosystem.md)（草案，待所有者确认开工前置）。
5. **真样本发现转为反面教材**：08 稿的 12 个无归属面 + 5 个工具缺陷提炼成 Phase 3 新插件评审的核查表（[design/phase-3/01](../design/phase-3/01-legacy-anti-patterns.md)）——旧生态的"能做到"从此是**拒绝理由的清单**，不是兼容待办。

## 明确不在本决定范围内

- **不删包、不动 vitest/eslint/prettier 配置**（`tests/cordis-*.test.ts` 与包内测试暂时照常进门禁；"兼容层测试是否移出主线门禁"是 Phase 3 的独立决定，理由见后果 3）
- **不撤回任何既有 ADR**：ADR-0010（运行期注册通道）、0011（装载门）、0012（策略舱与 `policy.hook`）、0013（流式拉式分片）都是**内核决策**，原生生态同样要用；ADR-0001/0002/0006/0007 与本决定无关
- **不打 tag、不改版本号策略、不宣称"旧插件不可迁移"**——只宣称"我们不再承接"

## 后果

正面：范围一次性收口，Phase 3 不必再背着"跟别人形态跑"的负债；不变量成为筛选标准而不是兼容障碍；已投入的五片仍有完整价值（内核能力、策略链、契约修订、声明合成、观察工具）。

负面与代价：

1. **兼容承诺作废**——若未来出现"必须承接存量插件"的真实需求，需要新写 ADR 重开，且 01 稿与 08 稿是重启的起点（决定可逆，成本已知）。
2. **01/02/04/05/06/07 六份定稿文档失去活性**：它们是"有损兼容的显式清单"这一路线的完整留痕，但不再前推。文档不删（决策链证据），状态一律标注"随 ADR-0014 冻结"。
3. **归档包仍在门禁里**：兼容层测试继续消耗每次全库复跑的时间，且会让下一轮会话误读"这些测试是主线要求"。这是**故意留的**：这些测试同时是内核通道 op（注册、装载门、策略 hook、流式、快照、drain）的**唯一真进程证据链**，删掉等于毁证。Phase 3 若要清理，必须先给这批内核断言找新家。
4. `keel observe` 的五个缺陷（D1~D5）**不再作为待修项**——但其中 D2/D3 是"观察工具给自己打分"的通用缺陷，Phase 3 的插件脚手架与验收工具会复用同一套合成/校验路径，因此转登为 Phase 3 开工前置的第 3 条。

## 备选方案（被否）

- **A 继续做到全量兼容**：形态在他方手里，每跟一次世代就重做一轮边界表；且真样本证明"跟上了也要拒"（第 3 条冲突）。
- **B 物理删除 `packages/cordis-adapter` 与其测试**：一次省时间，代价是丢掉内核六项能力的真进程证据链，且把已完成的五片变成无法复核的历史。
- **C 只改文档、不给包打归档标记**：包在代码层面仍是"主线一环"，下一轮会话与所有工具（包索引、README、CI 心智）都会继续按"兼容层待补"施工——本决定需要落在包自身，而不是只落在文档里。
