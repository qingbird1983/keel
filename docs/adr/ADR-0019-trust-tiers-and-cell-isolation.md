# ADR-0019：信任分层与 Cell 隔离加固

- 状态：接受
- 日期：2026-11-03
- 关联：[07 重构计划](../design/phase-3/07-runtime-context-refactor.md)；[ADR-0005](ADR-0005-cell-isolation.md)；[ADR-0018](ADR-0018-effect-receipts-and-workspace.md)

## 背景

07 稿把安全分成绿（纯计算/只读）、黄（受治理可逆写）、红（覆盖/越界/不可逆）、黑（raw IO）四条路径。当前进程后端：

- Cell 继承宿主完整环境变量与 cwd；
- Node 权限模型常被误认为沙箱；
- 一方插件与三方插件没有信任区分；
- 但若对所有插件一律加最严限制，安全路径会变得比绕开更长，违背“安全必须可用”。

## 决策

1. **信任分层**：manifest 可申请 `trust.rawIo: true`；宿主默认**不授予**（`AssemblerOptions.allowRawIo` 或受信名单显式授予）。授予结果写入 `ASSEMBLY_RECORDED` 的可选 `trust` 字段，供审计与评审；未授予的 raw IO 不被运行时“拦截”（当前后端没有系统调用拦截），但：
   - 不享受内置补偿（无收据）；
   - 评审按红/黑路径处理；
   - 后续容器/microVM 后端以同一字段作为放行依据。
2. **spawn 环境最小化**：Cell 只继承运行必需的白名单变量（Windows 的 `SystemRoot/windir/PATH/TEMP/TMP`，POSIX 的 `PATH/HOME/TMPDIR/LANG` 等）；不继承 `NODE_OPTIONS`、`*_TOKEN`、`*_KEY`、`*_SECRET` 等。白名单之外的变量不可见。
3. **cwd = 工作区**：若 manifest 的 `fs.write.allow` 能唯一确定一个根目录（形如 `fs:<root>/**`），spawn 的 cwd 取该根；否则保持默认并登记诊断。路径授权仍以 manifest 规则为准，cwd 只减少“相对路径写到家目录”的机会。
4. **Node 权限模型只作纵深防御**：默认不启用；提供 `nodePermissionArgs` 选项，启用时以 `--permission` + 工作区读写允许列表运行。文档与评审明确：它不是沙箱（官方声明不防恶意代码、符号链接可逃逸、Worker 不继承权限），不可信三方插件仍靠 OS 用户/容器/网络命名空间。
5. **绿/黄零审批**：纯计算/只读与工作区新建文件不需要额外审批；红路径（覆盖、越界、不可逆）才进入显式模式与策略/人工；黑路径需 trust 授予与评审。

## 备选与否决

- **默认启用 Node 权限模型**：会破坏大量合法插件（读取自身资源、临时文件），且不防恶意代码；否决，改为可选纵深防御。
- **所有插件都要求 trust 审批**：安全税过重，开发者会绕开；否决。
- **直接上容器/microVM**：超出本阶段，成本高；保留为后续后端，接口不变。
- **靠环境变量隐藏当作安全边界**：它只降低泄漏面，不是访问控制；在文档中如实说明。

## 后果

- 正面：一方插件零额外摩擦；三方/raw 有显式信任入口；环境泄漏面收窄；cwd 与授权一致。
- 负面：环境白名单可能导致少数插件缺变量而失败（可见失败，补白名单即可）；cwd 推导只在单一写根时生效。
- 边界：本 ADR 不宣称进程内沙箱；真正的隔离仍是 Cell 进程 + 后续容器后端。
- 契约影响：manifest 新增可选 `trust` 申请；`ASSEMBLY_RECORDED` 追加可选 `trust` 字段；`SpawnSpec` 追加可选 `env/cwd`。
