# 架构总览：Keel（龙骨）

- 状态：定稿（2026-11-02 所有者确认；内容为 briefs/Keel-Design-V0.1.md 的忠实蒸馏 + 已定 ADR 增量）
- 日期：2026-11-02
- 关联：[ADR-0001](../adr/ADR-0001-implementation-stack.md) ~ [ADR-0004](../adr/ADR-0004-ledger-consistency-point.md)；[roadmap/00-roadmap.md](../roadmap/00-roadmap.md)；[phase-0-design-baseline.md](../roadmap/phase-0-design-baseline.md)

## 1. 定位与命名

**Keel 不是插件框架，也不是 Agent 框架，而是 Agent Harness（"挽具"）的治理型运行时内核。**

命名语义：龙骨是船体底座——承载挽具的结构；水密隔舱对应执行单元强制隔离；压舱物对应预算/权限/停止条件等治理能力；航海日志对应可重放可审计的执行账本；船坞装配对应插件声明式装配（而非进程内全局注册表突变）。

设计立场：不是"再造一个更灵活的 Cordis"，而是把**控制面、隔离、账本、补偿、上下文治理**变成内核原语。插件仍然能装配、运行、热替换，但装配的是**能力，不是控制权**。

## 2. 设计目标与非目标

**目标**（对应第 2 节不变量）：

1. Agent 长程运行**控制不可旁路**；
2. 插件故障**不可级联**；
3. 会话状态**不可丢失、可恢复**；
4. 副作用**不可无痕**，必须有补偿路径；
5. 上下文与工具可见性**按作用域隔离**；
6. 支持插件**装配、运行、热替换**——插件只提供能力，不掌握控制权。

**非目标**：不重写所有能力插件；不追求理论上的"卸载即无痕"；不把 Agent Loop、预算、安全策略开放为普通插件；不要求一次性替换 DSH（先治理外挂 + 兼容层）。

## 3. 五大核心不变量

| # | 不变量 | 含义 |
|---|---|---|
| I1 | 控制不可旁路 | 调度、授权、预算、恢复、账本由内核掌握，插件不能替换 |
| I2 | 故障不可级联 | 故障边界 = 执行单元（Cell）边界 |
| I3 | 状态不可丢失 | 关键状态持久化，可从账本恢复 |
| I4 | 副作用不可无痕 | 越界副作用必须声明补偿语义 |
| I5 | 上下文不可全局污染 | 工具可见性、记忆、上下文按 Agent/Session 分区 |

## 4. 总体架构

```text
┌──────────────────────────────────────────────────┐
│                   Keel Core                       │
│  调度器 | 授权器 | 预算器 | 恢复器 | 账本          │
│  上下文管理器 | 模型网关 | 策略扩展点 | 插件准入    │
└───────────────────┬──────────────────────────────┘
                    │ 结构化请求/事件（唯一通道；ADR-0001：语言解耦点）
┌───────────────────▼──────────────────────────────┐
│                    Host Layer                     │
│  Cell Supervisor | 插件装配器 | 能力契约校验       │
└───────┬────────────────┬────────────────┬────────┘
        │                │                │
┌───────▼─────┐  ┌───────▼─────┐  ┌───────▼─────┐
│   Cell A    │  │   Cell B    │  │   Cell C    │
│  Agent Run  │  │  Agent Run  │  │  Agent Run  │
│ 私有工具表   │  │ 私有工具表   │  │ 私有工具表   │
│ 私有记忆     │  │ 私有记忆     │  │ 私有记忆     │
│ 私有上下文   │  │ 私有上下文   │  │ 私有上下文   │
│ 能力插件     │  │ 能力插件     │  │ 能力插件     │
└─────────────┘  └─────────────┘  └─────────────┘
```

> 图中"模型网关"为 ADR-0003 增量（简报原图无）：Cell 内一切 LLM 调用必经 Core 网关，保证预算权威记账。

### 4.1 Keel Core（控制面，不可插件化）

| 组件 | 职责 |
|---|---|
| 调度器 | 决定下一轮做什么，维护 Agent Loop 控制流 |
| 授权器 | 工具调用、网络、文件、付费 API 的准入 |
| 预算器 | token、时间、费用、工具调用次数硬上限 |
| 恢复器 | 从执行账本恢复到一致状态 |
| 账本 | append-only 事件记录，支持重放、审计、归因（一致点语义见 ADR-0004） |
| 上下文管理器 | 上下文分区、版本、换页、工具 schema 变更事件 |
| 模型网关 | LLM 调用唯一通道：授权 → 预扣 → 代理调用 → 权威计量入账（ADR-0003） |
| 策略扩展点 | 只开放受控 hook，不允许替换控制流 |

### 4.2 Host Layer（用户态宿主）

- **Cell Supervisor**：创建、监控、销毁执行单元；轮边界向 Cell 索取私有状态快照（恢复职责划分，Phase 0 A 任务细化）。
- **插件装配器**：发现、依赖解析、隔离加载、作用域绑定。
- **能力契约校验**：manifest、权限、资源、补偿语义、版本约束。

### 4.3 Cell（执行单元）

每个 Agent Run 一个 Cell，至少进程级隔离（MVP = OS 进程，演进期容器化，见 ADR-0005）。Cell 内：私有工具注册表（按 Session/Agent 作用域）、私有记忆与上下文页表、能力插件（崩溃不影响其他 Cell）；所有越界操作必须向 Keel Core 发结构化请求。

## 5. 插件模型

| 插件类型 | 能力 | 治理方式 |
|---|---|---|
| **能力插件** | 工具、模型适配器（仅协议适配，无凭证，ADR-0003）、文件/网络 I/O、记忆后端 | 跑在 Cell 内，按作用域绑定，内核授权与记账 |
| **策略插件** | 停止条件、预算、审批、重试策略 | 只能通过受控 hook 扩展，不能替换 Agent Loop |
| **观测插件** | 审计、告警、回放 | 只读账本，不能改控制流 |

插件包结构：manifest + 能力契约 + 资源需求 + 权限声明 + 补偿语义 + 版本约束（schema 设计 = Phase 0 任务 C）。

热装配原则：优先是**新 Cell / 新作用域切换**，不是进程内全局注册表突变；升级走版本化契约 + 状态迁移；失败按补偿链回退。

## 6. 关键机制

### 6.1 上下文作为一等资源

工具 schema 变更 = 显式、可观测、按作用域传播的事件；上下文分区、版本、换页由内核原语支持；不存在"全局工具注册表合并进所有会话"。

### 6.2 补偿事务替代 effect 回收

越界副作用记录补偿动作与依赖顺序；故障恢复或回滚时按依赖顺序执行补偿；承认不是所有操作可逆，但所有操作必须有补偿路径（状态机设计 = Phase 0 任务 D）。

### 6.3 执行账本

每轮决策、工具调用、预算消耗、状态转换写入账本；轮边界为一致点（CHECKPOINT 事件，ADR-0004）；支持从任意一致点重放恢复；调试 = 重放决策序列，不是翻插件日志。

### 6.4 隔离

Cell 之间不共享 Context、工具表、记忆；插件崩溃、泄漏、注册错误被约束在 Cell 内；工具可见性按 Agent/Session 分区。

## 7. 与 DSH / Cordis 的兼容与迁移

Cordis Adapter（有损兼容，承接存量生态）：`ctx.tools.register()` → Cell 作用域注册；共享 Context → 只读注入 + 显式能力申请；effect 回收 → 补偿声明。

迁移路径：阶段 0 治理外挂（工具作用域分区、进程级隔离、账本采集、补偿声明）→ 阶段 1 抽控制面 → 阶段 2 Cordis Adapter 兼容层 → 阶段 3 新插件生态（声明式 manifest）。对应本仓库 Phase 0~3（见 roadmap）。

## 8. MVP 范围

Keel Core 四件套（调度 + 授权 + 预算 + 账本）；Cell 进程级隔离 + 私有工具表；能力插件 manifest + 作用域绑定；越界副作用声明与补偿回退；只读/受控策略 hook；Cordis Adapter 原型。

## 9. 验收用例（DSH 症状 → 通过标准）

| # | DSH 症状 | 用例 | 通过标准 |
|---|---|---|---|
| V1 | 全局工具注册污染跨会话上下文缓存 | 20 个会话并发，动态增删工具 | 缓存命中率稳定，无全局污染（I5） |
| V2 | 插件崩溃拖垮进程 | 插件抛未捕获异常 | 仅该 Cell 失败，其他会话不受影响（I2） |
| V3 | 长程任务缺少统一执行账本 | 长程任务中断 | 可从账本恢复到一致状态（I3） |
| V4 | "卸载即无痕"在越界副作用上失效 | 工具调用失败 | 按补偿链回退，不宣称"卸载即无痕"（I4） |
| V5 | 热插拔依赖全局注册表突变 | 热装配升级 | 新 Cell/作用域切换，失败可回退（I1） |
| V6 | Agent Loop 被插件化导致控制流可被替换 | 审计归因 | 能重放任意 Agent Run 的决策序列（I1） |

## 10. 风险与边界

| 风险 | 说明 |
|---|---|
| 隔离成本 | 进程/容器隔离有开销，需要 Cell 池化与冷启动优化（roadmap 风险簿） |
| 兼容有损 | Cordis 共享 Context 语义不能原样保留，迁移边界须显式化 |
| 补偿语义复杂 | 需要标准补偿契约，否则退化为"日志里写一句" |
| 策略 hook 过度开放 | 必须白名单化，防止策略插件变相接管控制流 |
| 账本性能 | append-only 账本要支持分片、压缩、异步落盘（单机版先分段文件，ADR-0002/0004） |
