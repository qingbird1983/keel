## 1. 这份文档回答什么

一句话问题：**一张报关单都没有的旧插件，怎么在 Keel 上拿到"能过五步校验的那张单子"，而且这张单子不会顺手多给它从未用过的权力。**

三条主张（每条都有可断言落点，见 §7）：

1. **合成路径可自动化，且不破默认拒绝的口子**：观察运行在"越权一律当场拒"的策略下跑，插件每一次尝试都变成一条可读回的事实（`AUTH_DENIED` 的 `subject × action × resource`）；合成产物是**候选**，必须经审核 + 五步校验才进装配。
2. **声明是上界，不是通行证**：候选里多写的条目不放行任何未观察到的调用；每次调用重新裁决，拒绝留痕且两半都不写状态。
3. **存量插件的升级走同一条 V5 链**：新 Cell 验证 → 迁移钩（如有）→ 原子换绑 → 失败回退，并且**换绑之后这个 run 真的能跑**（今天跑不了，见 F3）。

本片**不做**（移交后续切片）：C 档三条改法与迁移手册（③）、D 档拒绝与策略 hook 装配链（④）、`throughSeq`/快照持久化/drain/流式（⑤）、真样本复跑与报告收口（⑥）。

## 3. 合成路径的形状（两遍观察 → 候选 → 审核 → 装配）

```
pass 1（全拒观察）    permissions=[] 的临时装配 → 承接层入口起舱 → 覆盖 driver 读可见表（此刻为空）
                      产出：AUTH_DENIED{action:"tool.register", resource:<name>} × N   ← 注册面全在这里
   ↓ 投影
候选 v1              {tool.provide, allow:[观察到的名字…]} + resources + compat
   ↓
pass 2（收窄观察）    用候选 v1 装配 → 注册成功 → 可见表非空 → driver 逐个调用每个工具（参数 = {}）
                      产出：TOOL_SCHEMA_CHANGED × N、TOOL_RESULT × N，以及其余越权的 AUTH_DENIED
   ↓ 投影合并
候选 v2 + gaps       候选 manifest（*.candidate.json）+ 缺项清单（补偿模板、观察不到的面、未覆盖的工具）
   ↓
人工审核              补 gaps → 转正为正式 manifest → `keel validate --manifest` → 通过才 bind/run
```

两遍而不是单遍的理由：pass 1 若放行 `tool.provide`，就已经在观察期开了一个越权口子（违反 I4）；全拒则看不到 handler 内部的调用面。分开两遍后，**第一遍只需要"注册被拒"这一种事实，第二遍的放行范围恰好等于第一遍观察到的下界**——放行的每一条都有账本凭据。

被否的替代方案：

| 被否方案                           | 否决理由                                                                                                                             |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 静态 AST 扫源码产声明              | 动态 `require`、条件分支注册、运行时拼名字会让"下界"都不成立（切片① 的四枚探针正是照这些写法设计的）；而且扫不出 `toolCallTimeoutMs` |
| 观察期先全放行、再按实际用量收窄   | 观察期本身就成了越权窗口，且"曾经放行"这件事在账本里没有可审核的形态                                                                 |
| 无报关单即拒绝装配（不做合成）     | 等于把 B 档判成 D 档，与所有者已确认的档位归类冲突，B2 一票否决项直接失败                                                            |
| 合成产物直接进装配（省掉人工审核） | 合同 §6 风险 2 写明"不以合成结果替代声明审核"；自动转正等于把审核责任推给内核，而缺项（补偿模板）本来就只有插件作者能补              |
| 让承接层替插件写补偿模板           | 补偿动作是插件作者的知识（`ctx.effects.reclaim` 的等价物），凭空造模板就是把"仅记录"伪装成"可逆"——静默降级                           |

## 4. 权限收敛口径（四条，写死）

1. **观察 = 拒绝并记录**：pass 1 的策略不含任何 `tool.register` 规则；注册面全部来自 `AUTH_DENIED`（F4）。
2. **声明编译是唯一规则源**：`manifestAuthRules` 接进 CLI 的运行时构造，观察运行与正式运行同源（F2 的消解）；硬编码 `p1` 只保留为"演示场景"的显式选项，不再是默认。
3. **逐次裁决，不缓存"曾经成功"**：每次调用重新 `auth.check`；同名再注册 = 版本 +1（ADR-0010 语义不变），不因上一轮允许过而跳过裁决。
4. **合成的 allow 只到观察到的资源为止**：不做通配扩展（观察到 `echo` 就写 `["echo"]`，不写 `["e*"]`）；名字排序去重保证同一插件两次观察产出字节相同的候选（可 diff、可复核）。

投影表（账本事实 → 声明条目）：

| 观察到的事实                                                             | 合成结果                                                                     |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| `AUTH_DENIED{action:"tool.register"/"tool.remove", resource:<name>}`     | `permissions[{cap:"tool.provide", allow:[…names]}]`                          |
| pass 2 成功的 `TOOL_SCHEMA_CHANGED{tool:<name>}`                         | 同上（合并去重）                                                             |
| `AUTH_DENIED{action:"model.invoke", resource:<model>}`（仅当调用经通道） | `model.adapter` + `allow:[model]`，**同时进 gaps**：越界能力需要补偿模板     |
| `AUTH_DENIED{action:"net.fetch"/"fs.read"/"fs.write", resource:<目标>}`  | 同上（`net.fetch`/`fs.*` + allow 目标），**并强制进 gaps**（模板 + reason）  |
| TOOL_RESULT 里 handler 因缺参/超时而未跑通                               | gaps："该工具的调用面未覆盖"（不假装覆盖完全）                               |
| 舱内原生 `fetch`/`fs`/SDK 直调                                           | **观察不到** → gaps 以"需人工声明"列出（F5），不得表述为"已确认不需要该能力" |

`meta` 的合成规则：`name` = 插件文件名的 kebab-case 规范化（schema 要求 `^[a-z][a-z0-9-]*$`，故 `tierA-01-toolset.cjs` → `tiera-01-toolset`）；`version` 缺省 `0.0.0`（合成版本不是发布版本，转正时由作者改写）；`description` 写明来源（观察 run 的 runId 与候选序号，≤400 字），这样 `ASSEMBLY_RECORDED` 里就能看出这张单子的来历。

## 5. B6：升级路径与装配编排的接缝

三处补缝，全是"把已有的两条线接上"，不新增能力：

1. `BindRequest` / `HotSwapRequest` / `CellFactory.spawn` 增可选 `cellEntry`（Supervisor 侧切片① 已支持 per-spawn 覆盖）→ 承接层插件能被编排。
2. **新增 host 层收敛点 `wireCell()`**：把 `spawn → serve → alloc` 三件事收成一个函数（今天这三步散落在 `wireRun` 与两处测试 rig 里）。工厂返回的 `ManagedCell` 通道已服务，`AssemblyManager` 仍只管绑定表 → 换绑之后的新 Cell 天然能用 `tool.register` 与 `tool.exec`（F3 消解）。`wireRun` 改为调用它，rig 同步（不改主张）。
3. 就绪时机（§6）落在同一处：`wireCell()` 返回前完成一次就绪探测，装配/升级/起 run 三条路共用。

旧插件升级的两条真实差异（不掩盖）：

- **无迁移面**：旧插件不导出 `migrate`（那是新生态形状），承接层也不代它实现 → 带 `migration` 声明的旧插件在首个 `cell.migrate` 处拿 `CELL/MIGRATION-MISSING`，`hotSwap` 当场回退（V5 的回退主张照样成立）。B6 因此断言两条：无 `migration` 的旧插件成功原子换绑且换绑后 run 真跑；声明了 `migration` 的旧插件当场回退、旧绑定原样、账本无全局突变痕迹。
- **合成产物一律不含 `migration`**：跨版本状态迁移是作者知识，观察不出来（§12 限制 4）。

## 6. 就绪时机的正式解法（收口 02 稿 §12 第 5 条）

切片① 用测试侧屏障绕过这个问题，本片把它转正。三条路：

| 方案                              | 做法                                                                                                                          | 代价                                                                                                                |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **A（已采纳）** 装载门 + 既有探测 | `startCell` 增加"装载完成前不应答"的门（入口在 activation 结束后 `markReady()`）；宿主以一次 `cell.snapshot` 应答作为就绪凭据 | 改变 Cell 的应答语义（"立即应答"→"装载完应答"）→ 需契约 §3.1/§7 注记 + **ADR-0011**；装载期请求排队，要给定超时口径 |
| B 新 op `cell.activated`          | 舱内 activation 结束后向宿主报到一次                                                                                          | 可见面矩阵再加一个 op，且这个 op 没有裁决语义（纯信号）——内核要多认识一件它不需要认识的事                           |
| C 事件帧 `ev:"CELL_ACTIVATED"`    | 用 §3.1 已定义但 MVP 无推送方的事件类                                                                                         | 事件类语义是"账本事件按订阅分发"，挪用为生命周期信号 = 重新解释契约，还要定义接收方义务                             |

**定案 A**（§10 第 1 项）：**不加 op、不重新解释事件类**，"就绪"就是"这个舱能应答 `cell.snapshot`"这一条既有事实的强化。默认入口的门在装载末尾显式打开（现状即"装载后才应答"，显式调用是为了让遗漏在测试里表现为超时而不是偶发空表）；承接层入口在 `await activate(ctx)` 之后打开。探测**单次、不重试**，超时口径 = 5s（与契约 §7 的 `run.start` 冷启动同源）；超时或通道断 → 宿主 `dispose` 该 Cell（`killed` 分类）并拒绝装配。

## 10. 所有者确认结果（2026-11-03，三项均按建议）

1. **就绪时机 = 方案 A**（装载门 + `cell.snapshot` 就绪探测）→ 已立 [ADR-0011](../../adr/ADR-0011-cell-load-gate.md)：`CellHandle.markReady()`、门未开时请求排队不应答、探测超时即拒绝装配并 `dispose`（`killed` 分类）、契约 §3.1/§7 各补一条注记；生命周期阶段语义与 bootstrap 载荷**不动**。
2. **候选必须经人工审核转正**：合成产物落盘为 `*.candidate.json` + 缺项清单，审核者补齐后才作为正式报关单进五步校验与装配。本片**不做自动转正**，也不给自动转正开"看起来安全"的特例（如"无缺项即自动通过"）——合同 §6 风险 2 的口径按原文执行。
3. **边界表 #4 与 #12 改判 C 档**（以"实现期细化"追加注记，其余档位与 D 档零例外不动）：#4 的改法 = 声明所需能力 + 经通道调用，密钥不再由插件持有；#12 的耦合在作用域隔离下结构上不存在（切片① 的 `probe-order` 已实证），改法 = 把"指望别人先注册"改成显式工具调用或只读账本。**注意这条改判会缩小 B 档集合**：01 稿 §4 的"补一张报关单"汇总行只剩 #5 与 #11 两行，本片的合成路径因此主要是为这两行服务，其余交给切片③ 的迁移手册。

## 12. 本片的限制（先登记，别等报告）

1. **经通道才看得见**：模型 SDK 直调与原生 `fetch`/`fs` 观察不到，候选对这些面天然缺项；gaps 清单负责显式承认，不得把"没观察到"写成"不需要"（F5；进程后端不变，容器后端触发条件见 ADR-0002/0005）。
2. **覆盖 driver 用空参数**：handler 因缺参或超时而没跑通的，其内部调用面记为"未覆盖"；人工参数注入留 backlog，不在本片做。
3. **真正被收敛的 cap 目前只有 `tool.provide`**：其余 cap 的 allow 清单只能来自"被拒资源"这一种事实，且必须人工补补偿模板与理由。
4. **旧插件没有迁移面**：带 `migration` 声明即在首个迁移调用处失败并回退；"有状态旧插件的跨版本迁移"属切片③ 改法。
5. **B2 的"多声明不放行"是硬拦截断言，但只覆盖经通道的写口**（`tool.register`/`tool.remove`）；其它 cap 的越权只能断言到"授权规则按 allow 逐条收窄"这一层，表述时不得升格为"一切越权都被拦下"（与 F4/F5 同源）。
