- **切片③.5 运行上下文重构**：写文件从"直接写"改为"底座代写并发收据"——撤销只认收据（不是本次创建的不删、被换过的不删、覆盖写不删），误删从"靠自觉"变成"结构上做不到"；重试幂等、生命周期收尾、环境隔离与信任分层（ADR-0017~0020）
- **切片④插件 B/C 转正**：写文件插件纯 handler 一行业务（C3 真进程补偿闭环：注入故障 → 只删本次创建 → 账本全链）；参数守门策略插件否决"内容含敏感标记"的写请求（路径守卫结构上看不到的面），介入逐条可从账本归因，杀掉策略进程运行也不崩（C4）
- **切片⑤验收复核与报告收口**（本轮）：C1~C7 逐条对账打勾；规范回填复核（两处缺口补注记）；插件开销基准复采（见 §2）

## 2. 插件开销基准（B6，切片⑤新增口径；只测量不设阈值）

`keel bench` 同轮采集（2026-11-04，win32/x64，node v26.13.0）；三行同族口径 = 直连执行单元的单次往返（真实子进程 + stdio 通道），互相横向对比：

| 指标                | 口径                                                     | 结果                 |
| ------------------- | -------------------------------------------------------- | -------------------- |
| B6a echo 全链       | 热舱直连往返 N=20（零治理对照）                          | min/p50 = 0.1/0.2 ms |
| B6b write_file 全链 | 热舱直连往返 N=20（含授权 + 守卫 + 自动声明 + 收据落账） | min/p50 = 1.2/1.3 ms |
| B6c 策略插话        | `toolApproval` 跨进程往返 N=20（独立策略舱）             | min/p50 = 0.2/0.2 ms |

初读：治理满配比零治理对照贵约 1 ms（授权、声明、收据落账的宿主侧开销），策略插话一次跨进程往返 0.2 ms——"安全路径最短"的代价可量化且很小。内核既有基准（B1~B5）同轮复采同量级（B1 23932 events/s、B3 冷启 44/46 ms），三个 ADR 重评条件无触发迹象。
