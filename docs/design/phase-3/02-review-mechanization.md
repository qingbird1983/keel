## 1. 这份文档回答什么

01 清单是"人读的否决清单"；本稿把它翻译成**机器可执行的禁面符号表**，并给出三件套的需求卡与留痕模板。评审从此分两层：机器层（扫描零命中，每次门禁都跑）+ 人工层（REVIEW.md 逐条留痕，转正时一次性写）。机器层不能替代人工层——正解类条目（如 A1 的 manifest 声明路径）机器判不了——但机器层能保证**已知的坑不再靠记忆防**。

## 4. 三件套需求卡（所有者 2026-11-03 选型定案）

> 每卡五栏：验证点 / 不变量锚 / 范围 / manifest 声明面 / 验收口径。命名定案：`packages/plugins/echo/`、`packages/plugins/file-write/`、`packages/plugins/param-guard/`。

### 插件 A：`echo`（只读工具）

- **验证点**：授权与工具发现——manifest 报关单是工具可见的唯一来源；装载门就绪凭据；scope 隔离。
- **不变量锚**：I1（控制不可旁路）、I5（上下文不可全局污染）。验收口径：合同 C1【一票否决】。
- **范围**：一个工具 `echo`，原样返回输入文本；不碰文件系统、不调模型、不注册第二个工具。**不做**：任何 IO。
- **manifest 声明面**：单能力 `tool.provide`（一个工具描述）；无资源、无补偿（无副作用）。
- **验收口径补充**：跨两个 session 装配，工具表互不可见；未授权调用被拒且 `AUTH_DENIED` 落账本。

### 插件 B：`file-write`（越界工具 + 补偿模板）

- **验证点**：`EFFECT_DECLARED` 与补偿闭环——越界副作用必须先声明补偿语义，未声明的写当场拒绝、零部分生效。
- **不变量锚**：I4（副作用不可无痕）、I3（状态不可丢失）。验收口径：合同 C3【一票否决】。
- **范围**：一个工具 `write_file`，只允许写 manifest allow 清单内的目录；补偿动作 = 删除该文件（可逆分级）。**不做**：目录遍历、追加模式外的写语义、清单外路径（应被拒）。
- **manifest 声明面**：能力 `fs.write` + `paths.allow` 清单 + 补偿模板（`remove` 语义）。
- **验收口径补充**：注入故障（补偿前崩溃/回滚指令）→ 补偿按依赖序执行 → 文件消失且账本有 `EFFECT_*` 全链留痕；清单外路径写入被拒且无部分写入。

### 插件 C：`param-guard`（策略插件）

- **验证点**：`policy.hook` 介入与账本留痕——策略代码跑在自己的进程，拦截危险参数，介入逐条可归因；策略进程崩溃不级联。
- **不变量锚**：I1（策略白名单插话，不变相接管控制流）、I2（故障不可级联）。验收口径：合同 C4。
- **范围**：对 `write_file` 类工具调用的参数做否决/放行（如拒绝 `path` 越出清单）；只用白名单 hook。**不做**：改写参数、替插件重试、任何自带 IO。
- **manifest 声明面**：策略声明（绑定的插话点 + 拟拦截的能力名）；无工具、无资源。
- **验收口径补充**：危险参数被拦且 `DECISION.basedOn` 含策略介入事件 seq；kill 策略进程 → run 走既有 fallback 不崩（B7① 口径延续）。

## 5. 留痕口径（每插件一份 `REVIEW.md`，转正时一次性写）

模板五段：① manifest 摘录（能力/资源/补偿三项）；② 01 清单 18 行逐条——"不适用 + 一句理由"（或命中即不得转正）；③ 看代码三件事的结论（入口形状 / 工具体字段 / import 清单零三方依赖）；④ 门禁与真进程用例的退出码证据；⑤ 不可观察面清单（D5）与人工补声明记录。
