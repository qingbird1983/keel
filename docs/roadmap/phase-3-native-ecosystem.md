## 1. 目标

不再承接旧生态，改为**为 Keel 原生 manifest 规范打造第一批"少而精"的标杆插件**：每个插件从一个真实需求出发、只做一件事、满足全部核心不变量（I1~I5），用真实进程证据证明"按规矩写的插件在 Keel 上是什么样子"。产出物同时是三样东西：可用的功能、manifest 规范的实战检验、后来者的参考实现。

## 2. 范围

### 做

- **首批标杆插件**（数量与选型见 §6，待所有者定）：每个插件一页"需求卡"（要解决什么、为什么值得进库）+ manifest 报关单 + 实现 + 真进程测试
- **评审流程机械化**：把 [反面教材清单](../design/phase-3/01-legacy-anti-patterns.md) §5 的五步评审落成可执行核查（符号扫描扩展到"原生插件不允许出现的面"，逐条留痕）
- **manifest 规范实战检验**：标杆插件装配全程走既有五步校验；发现规范缺字段/歧义 → 登记并走 ADR 修订（不临场发明 API）
- **内核能力直接使用**：`model.invoke`/`model.stream`（流式记账四条不变式）、补偿声明、快照恢复、策略链——Phase 2 沉淀的内核能力由原生插件作为第一用户验证
- **`keel observe` 复用为新插件脚手架**：合成/校验路径转向"声明 → 校验 → 运行观察核对声明与实际调用面一致"

### 不做（明确排除）

- Cordis/DSH 旧生态兼容与迁移（已终止，ADR-0014；承接层归档）
- 运行中提权、提示词贡献、自算预算、concludeTurn 等 18 类反面教材面（命中即退回，无"例外申请"）
- 三方运行时依赖（继承 Phase 1 起的零依赖纪律；插件自身同样遵守）
- 容器/microVM 隔离、分布式、账本存储引擎独立化、旁路计量（backlog 触发条件不变）
- 观测生态与跨 run 账本读取的完整建设（若首批标杆有真实需求再立项，先 backlog）

## 3. 开工前置条件

- [ ] **本合同定稿**：三处待决（首批插件清单 / 验收场景 / 门禁归属）由所有者确认

- [ ] **归档包测试的门禁归属**：`packages/cordis-adapter` 与 `tests/cordis-*.test.ts` 是内核通道 op 的唯一真进程证据链（ADR-0014 保留物）。建议保留在主门禁直至原生插件测试对同一批通道 op 形成等强度覆盖，届时再移出——**由所有者定**
- [x] 工具链 / 门禁 / 远端 / 许可证与署名（Phase 1 起就绪，无变化）

## 5. 验收场景（草案，定稿时可补删）

> 标注【一票否决】的场景未通过时不得打 `phase-3.end` tag。

- [ ] **C1【一票否决】** 装配与运行全通过既有五步校验，零豁免：每个标杆插件 manifest → 五步校验 → 真进程 run 跑通主场景，账本完整
- [ ] **C2【一票否决】** 反面教材零命中：符号扫描扩展后，每个插件对 18 类否决面**机械核对零命中**；人工评审留痕"依据了哪几条、为何不适用"
- [ ] **C3** 声明与实际一致：运行观察核对插件实际调用面 ⊆ manifest 声明；越权调用被授权器当场拒绝并留痕（多声明不放行的镜像面）
- [ ] **C4** 零三方运行时依赖：依赖树机械核对（插件与实现包同标准）
- [ ] **C5** 有副作用的插件补偿可回滚：声明补偿动作 → 注入故障 → 回滚闭环有账本证据（I4）
- [ ] **C6** 用到模型的插件走 `model.invoke`/`model.stream`：记账四条不变式（授权一次/预扣一次/`MODEL_INVOKED` 一条/每片不写事件/终局 settle）有测试钉住
- [ ] **C7** 决策可归因：任意 run 的决策序列可从账本重放（V6 延续，`throughSeq` 语义下）
- [ ] **C8** 门禁与回归：六道门禁全绿；Phase 1 A1~A8 与 Phase 2 保留主张（B2/B3/B4/B6/B7）不退化

## 6. 首批标杆插件候选（草案，待所有者选定 2~3 个）

> 选型原则：覆盖"只读 / 有副作用 / 用模型 / 不用模型"四个象限至少三个；每个都必须对应一个真实需求（所有者的日常或 Keel 自身的开发流程），不接受假想需求。

| 候选               | 一句话需求                                            | 象限            | 顺带验证的内核能力                                |
| ------------------ | ----------------------------------------------------- | --------------- | ------------------------------------------------- |
| P-A 会话日志整理器 | 把账本目录里的 run 记录整理成人类可读的交接摘要       | 只读 + 模型     | `model.invoke`/`model.stream` 记账、`ledger.read` |
| P-B 仓库文档体检器 | 扫 docs/ 与 .agents/ 的体量红线与孤儿文档，输出体检单 | 只读            | 最小声明面、I5（不污染会话上下文）                |
| P-C 文件归档器     | 按规则移动/归档文件，误操作可回滚                     | 有副作用        | 补偿声明与回滚闭环（C5）                          |
| P-D 发布流水线插件 | 门口禁 → 提交 → 合并 → 推送的受控编排                 | 有副作用 + 模型 | 策略链、补偿、快照恢复、C7                        |

## 7. 依赖与风险

- 依赖：Phase 1~2 的内核能力（已全部在库并各有真进程证据）；Phase 2 合同 §8 保留物
- **风险 1：需求不真**。"标杆"最容易退化成"自嗨样本"（恰是真样本复跑里合成样本被证伪的同款问题，[P-013](../../.agents/pitfalls/P-013-用合成样本校准形状分布必然偏窄.md)）。缓解：需求卡制度 + 所有者亲自点名需求
- **风险 2：规范缺口临场发明**。manifest 规范没覆盖的诉求出现时，最危险的应对是插件自己想办法。缓解：缺口 → 登记设计稿 → ADR 修订 → 才实现（铁律 1 对插件同样生效）
- **风险 3：反面教材清单过期**。清单来自旧生态证据，可能漏掉新写法的坑。缓解：每接一个新插件回填清单（沿用 01 稿的回填义务形状）；清单只增不改
- 估时：待首批插件选定后估（不预估，避免数字先行）
