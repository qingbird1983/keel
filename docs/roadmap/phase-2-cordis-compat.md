- 状态：**草稿**（待所有者确认；一经确认即转定稿并打 `phase-2.start`。定稿前不写实现代码——铁律 1 / standards/03）

## 1. 目标

让按旧框架（Cordis）写的存量插件能在 Keel 上运行——**按迁移边界文档逐档承接**：A 档零改动、B 档补声明、C 档给明确改法、D 档硬拒绝。产出可复用的承接层与一份被真实插件验证过的边界清单，把"生态迁移可行"从主张变成有账本证据的事实。

## 2. 范围

### 做

- **承接层实体化**（`packages/cordis-adapter` 从接口级原型扩成运行期承接层）：旧 `ctx.*` 面到 Keel 受控等价物的映射、A/B 档自动化、C 档迁移样例、D 档显式拒绝
- **manifest 合成路径**：存量插件无报关单 → 从运行观察收敛权限/资源/补偿声明，产出合成 manifest 后进五步校验（Phase 1 明文不做，本阶段做）
- **验收插件组**：按 §3 决定的材料（真实样本 / 合成样例组）建立可复跑的插件集与其预期边界归属
- **策略插件 → hook 总线装配链**（Phase 1 登记限制；边界表 #14 的承接前提是这条链通，默认纳入——若移出需所有者确认并记入报告）
- **迁移手册**：给存量插件方的改写指引（每条 C 档一个 before/after 样例），落 `docs/design/phase-2/`

### 不做（明确排除）

- 观测插件生态与跨 run 账本读取（Phase 3；本阶段只保留既有只读面）
- 新插件生态的声明式替换、能力契约全面替换存量模式（Phase 3）
- 容器 / microVM 隔离后端、分布式与多机（backlog，触发条件见 ADR-0002/0005）
- 静默降级式兼容：**任何映射不到的旧写法不得"凑合跑"**（这是 D 档存在的全部理由）
- 真实模型凭证托管与安全边界重划（沿用契约 §4.7；如需变更另立 ADR）
- 性能优化（只复采基准，观察承接层引入的开销）

## 5. 验收场景（逐条可执行；结果记入 `design/phase-2/report.md`）

> 标注【一票否决】的场景未通过时不得打 `phase-2.end` tag。

- [ ] **B1【一票否决】** A 档零改动迁入：验收插件集里判定为 A 档的插件，**一行不改**在新内核跑通——各自账本完整、会话间工具表互不可见、崩溃只伤本舱
- [ ] **B2** B 档补声明即通：无 manifest 的旧插件经合成路径产出报关单 → 五步校验通过并运行；合成声明若**超出实际调用面**，被授权器按词表拒绝（不得因"只是多声明"而放行越权调用）
- [ ] **B3** C 档改法有效：三条各出一个可跑样例——#6 模型调用改走网关（预扣/实结/同 id 重放不重复计费）、#8 共享可变状态拆分、#9 副作用回收改声明式补偿并实测回滚闭环
- [ ] **B4【一票否决】** D 档硬拒绝且零部分生效：试图替换调度、自建预算记账、以策略插件绕控制面的插件——被装配期或运行期拒绝，留痕可查，且**没有任何一条能力悄悄生效**（静默降级 = 直接失败）
- [ ] **B5【一票否决】** 边界闭环：验收插件集中出现的每一个旧 API 符号都能在边界表找到归属行；出现未归类符号即视为验收未过，先补表再收口
- [ ] **B6** 升级路径沿用 V5：存量插件版本升级 = 新 Cell 验证 → 迁移钩 → 原子切换；迁移钩失败回退旧绑定，全程无全局注册表突变痕迹
- [ ] **B7** 回填项达成（按 §3 确认结果裁剪）：默认含"策略插件 → hook 总线"——真实 run 中四个白名单 hook 的介入均可从账本归因（承接 Phase 1 A6 口径）
- [ ] **B8** 质量与开销：六道门禁全绿、Phase 1 的契约级五测试点不退化；承接层引入的额外延迟有基准数据（只测量不设阈值）

## 6. 依赖与风险

- 依赖：Phase 1 全部产出（已完成）；Phase 2 开工前置三项（§3）
- **风险 1（最高）：验收材料自证**。若无真实存量插件而用合成样例，"迁移可行"的证据强度会降一档——真实世界的野路子（动态 require、原型链猴子补丁、进程级全局 hack）不在我们的想象清单里。缓解：合成组按"最坏写法"设计，边界表 §5 的符号回填义务照常执行；报告如实标注材料性质
- 风险 2：manifest 合成的权限收敛口径。太松 = 越权放行（违反 I4 默认拒绝）；太严 = 存量插件全被拒（迁移失败）。缓解：合成产出"最小可用声明 + 运行观察追加"，越权一律当场拒绝并留痕，不以合成结果替代声明审核
- 风险 3：D 档清单会遭遇存量方的现实压力（#7/#14 正是旧框架最普遍的写法）。缓解：拒绝姿态不改，改的是**迁移手册给出等价出路**（hook 白名单 + 内核预算/调度能力）
- 风险 4：策略 hook 装配链接入后，Phase 1 已绿的归因主张可能被改写（新增事件类型/写入源）。缓解：契约 §9 测试点作为回归底线（B8 明确"不退化"）
- 估时：待 §3 三项确定后由所有者与 AI 共同回填（Phase 1 实测：单人从施工到收官，八场景 + 规模级补执行；Phase 2 的规模主要由验收插件集大小驱动，非代码量）
