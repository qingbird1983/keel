# P-021 金额浮点求和噪声让预算断言飘

## 现象

切片③计价测试里 `budget.query(ref).run.used` 期望 `0.7`，实际 `0.7000000000000002`。
`MODEL_USAGE.cost` 已经是 `0.7`（计价函数收过一次），预算账却仍是脏尾数。

## 根因

结算是"先预扣、后实结"的差值运算：`used += actual - estimate`。`0.7` 与 `5` 相减再相加，
二进制浮点无法精确表示，尾差留在 `used` 上。计价函数的四舍五入只管事件载荷，管不到预算器
内部的累加。

## 修复

- `Budgeter.settle` 在每次累加后统一 `tidy(n) = Math.round(n * 1e12) / 1e12`（两级用量同口径）。
- 计价函数 `priceUsage` 也做同量级的收口（`1e12`），保持"事件里的金额"与"账上的用量"一致。
- 断言直接比金额（`toBe(0.7)`），不写容差——容差会把下一次更严重的误差也放过去。

## 预防

- 凡是"金额/抽象计量"的累加，都在**写入状态的那一处**收口；不要指望调用方先算干净。
- 计价与预算分属两个模块时，两边用同一收口位数，避免一个 0.7、一个 0.7000000000000002。
- 回归锚：`packages/core/test/budget.test.ts` 超支用例、`packages/core/test/pricing.test.ts`
  的浮点断言。

## 证据

`packages/core/test/budget.test.ts`：修复前 `used` 飘尾数；修复后 `{limit:50, used:50, remaining:0}`
与 `{limit:0.5, used:0.5}` 均精确相等。
