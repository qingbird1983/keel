# P-018：外部 API 事实会过期——凭记忆写就是写已停用的名字

- 日期：2026-11-04
- 触发场景：Phase 4 模型插件设计稿的 manifest 示例写了 `deepseek-chat`

## 现象

示例与验收口径用了 `deepseek-chat`；所有者指出该模型已于 2026-07-24 停用，现行只有 `deepseek-flash` / `deepseek-v4-pro`。若不改，真适配器第一次调用就会失败。

## 根因

- 模型名、价格、参数默认值、端点都是**外部会漂移的事实**，训练记忆里的版本没有时间锚；
- 设计稿写示例时按"常见写法"落笔，没有回到官方文档核对；
- 项目里当时只有 DSH 的调研（research/01），没有 provider 的现状文档。

## 修复

按所有者提供的官方调研核对，全部示例改用现行名；把事实沉淀为 [research/02](../../docs/research/02-deepseek-api-survey.md)，并连带修正计价（三桶×峰谷）、`reasoning_content` 回传、思考模式默认开启三处设计。

## 预防

- 凡外部事实（模型名、价格、端点、参数默认值、限流），写进 docs 时必须带**来源 URL + 检索日期**，并单列"未确认清单"；
- 设计稿里的可执行示例只用"已核对的现行值"，停用值只允许出现在"已停用"说明里；
- `briefs/` 只作输入，对齐后立刻沉淀 `docs/research/`（本次即 research/02），下次直接引文档而不是引记忆。
