# P-004 类型检查依赖构建产物：干净环境必炸，本机永远绿

- 环境：2026-11-02 首次推送 GitHub 远端，CI `pnpm typecheck` 步骤失败（本地同命令此前每次绿灯）

## 现象

- `Cannot find module '@keel/core' or its corresponding type declarations`（TS2307），三处同现：`@keel/host`、`@keel/cordis-adapter`、`apps/keel`
- 派生噪音：因为解析不到类型，回调参数全部退化成隐式 any（TS7006 一串）——真正的病灶只有一个：模块没解析到
- 只在 CI 出现；本地 `pnpm typecheck` 无论怎么跑都过

## 根因

1. 各包 `package.json` 的 `exports.types` 指向 `dist/index.d.ts`——**跨包类型引用的落点是构建产物**。
2. 门禁顺序（standards/04 §1）= fmt → lint → **typecheck** → build → test，即类型检查天然跑在构建之前。
3. 干净检出时 `dist/` 不存在（`.gitignore` 排除），第 1 条的引用无处落地；开发机上因为历史构建残留 `dist/`，同一命令永远"看起来是对的"。
4. 结论：本地绿灯来自**热缓存**而非规范达成——这类缺陷只有换一台干净机器才会现形，远端流水线正是那台干净机器。

## 修复

- 各包的**类型检查专用**配置（`tsconfig.json`，`noEmit: true`）加 `paths`，把 `@keel/*` 直接映射到兄弟包 `src/index.ts`：类型检查期读源码，不再要求"先构建"。
- **构建配置（`tsconfig.build.json`）不动**：仍走 `exports` → `dist`，`pnpm -r run build` 的拓扑序保证被依赖包先构建；发布面的类型仍然来自 `.d.ts`，没有把源码当成发布物。
- 顺带把 `apps/keel/tsconfig.json` 的 `include` 补上 `test`（此前 CLI 测试不在类型检查范围内）。

## 预防

1. **收尾核对加一条**：`pnpm clean` 之后完整跑一遍六道门禁（`pnpm format:check && lint && typecheck && build && test && bash scripts/check-size`），退出码取真实状态（别 `| tail` 把失败吞成 0）。启用远端后每阶段至少做一次。
2. **新包接入时**：只要它 import workspace 兄弟包，就在它的 `tsconfig.json`（非 build 那份）里加对应 `paths`；漏加的表现就是本条现象。
3. 与 [P-002 规则 4](P-002-集成测试装配接线四类错.md) 是同一事实的两面：**运行时**（vitest/子进程）解析走 `dist`，**类型期**解析现在走 `src`。改完 `src` 要跑集成测试仍需先 build。
4. "本地全绿"不是规范达成的证据——CI 的价值就在这儿：把它当成第一次真跑，而不是形式。
