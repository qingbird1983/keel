# P-013-用合成样本校准"真实世界有多少形状"必然偏窄

> 单篇 ≤ 80 行；已检索 P-007（绿色要当场验真）与 P-006（时序屏障）——那两篇管**真进程测试怎么写**，本篇管**验证材料本身是怎么来的**：合成样本的形状是设计者定义的，于是它证明不了"形状的分布"。

## 现象

Phase 2 的边界表（01 稿）15 行 + 三档 C 改写面 + D 档拒绝组，全部由合成样本 `tests/fixtures/cordis-plugins/*.cjs` 驱动验证，六道门禁与 431 项测试全绿。第一批三枚**真实第三方插件**（`dsh-plugin-local-life` / `dsh-scrape-webpage` / `@99galaxy/dsh-turn-notify`）打过来时：

- **三枚没有一枚走到 ctx 面**——两枚死在 `ADAPTER/ENTRY-UNKNOWN`（入口形状），一枚死在 `ERR_MODULE_NOT_FOUND`（按 npm 名 import 宿主包）。边界表是为"进了 ctx 之后"准备的，前置门槛上**一行都没有**。
- 三枚合计暴露 **12 个在 15 行里无归属的旧形状面**：`export const name/inject/Config` + `export function apply(ctx, config)`、`ctx.provide/get/inject`、`ctx.systemPrompt.section`、`ctx.effect`、`exec` 参数（含 `deferContext` / `concludeTurn`）、运行中沙箱升级 + 人工审批、外部组合层 `cordis.patch.yml`、浏览器半 `dsh.client.platform="web"`……
- 反过来，我们花最多力气的几条（`ctx.llm` 自带 SDK、`ctx.share`、`ctx.bus`、`ctx.effects.reclaim`、`ctx.hooks`）在真样本源码里**出现 0 次**。
- 承接层认的三种入口形状里，两种（`module.exports=fn(ctx)`、`{activate(ctx)}`）在当前 Cordis 世代不是主流或已不存在——`@deepseek-ai/cordis@4.0.5` 的 `src/registry.ts` 只定义 `Function(ctx,config)` / `Constructor` / `Object{apply(ctx,config)}`，**没有 `activate`**。连 `ADAPTER/UNKNOWN` 文案指出的迁移方向都是历史形状。
- 工具定义字段名也不同：真实形状是 `parameters` / `execute(args, exec)` / `output.render` / `timeoutMs` / `isConcurrencySafe`，我们按 `(name, schema, handler)` 读——**若只补入口识别不补字段名，会注册出"有名字、无 schema、无处理器"的工具，即静默降级**（姿态 1 禁止的那件事）。

## 根因

**合成样本的形状由设计者定义，所以它只能证明"我们设想的写法可行"，不能证明"真实写法只有这些"。**合同 §6 风险 1 早已点名这件事（"材料自证"），处置是"报告分两批如实标注证据性质"——标注做了，但**没有人规定档位判据要按真样本重开一轮**，于是标注成了免责声明而不是工序。四件事叠加造成偏窄：

1. 旧形状是我们按记忆写的，不是按发布物写的（世代差一个：我们写的是 `activate` 时代，市场上是 `apply` 时代）；
2. 合成 fixture 是**单文件**，不需要 `package.json`、不需要外部声明层、不需要跨文件模块——于是"声明不在代码里"这类形态根本进不了视野；
3. 装载失败这一整类失败形态从没进过门禁（fixture 永远能装载）；
4. `keel observe` 的验收测的是"能合成出候选"，不测"装载失败时候选该长什么样"（详见 [P-012](P-012-观察命令的ACCEPT不等于观察到了东西.md)）。

## 预防

- **任何"覆盖率/闭环"类主张（B5 这种）都必须有一批材料不是自己写的**；自己写的部分只能标"设想覆盖"。写报告时分两批，写看板时也分两批。
- **形状类判据落笔前先取一手来源**：框架的 `.d.ts` / 注册函数源码 / 发布物的 `package.json`。"我记得旧框架是这么写的"不是依据；三枚样本 n=3 也不是依据（下一批要专门挑**真用了** `ctx.llm`/`ctx.share`/`ctx.bus` 的历史世代插件，否则会得出"这些写法现实中没人用"的错误结论）。
- **每次档位修订记录"第几号真样本暴露的"**（沿用 01 稿"实现期细化"注记格式），否则第二轮补表又会被当成第一轮的一部分。
- **fixture 保真度纪律**：真实包结构（含 `package.json` 与外部声明层）优先于"最小可跑文件"。最小文件省的是我们的功夫，丢的是分布信息。
- 顺带一条：**入口/装载这一层的失败要当独立一档看待**。它不属于 A/B/C/D 任何一档——它是"能不能开始谈档位"的前置条件，写表时容易整层漏掉。
