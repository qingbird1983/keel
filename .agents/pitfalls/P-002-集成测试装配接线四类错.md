# P-002 集成测试装配接线：四类错（参数位、顶层捕获、定位法、dist 解析）

- 环境：切片④ A3/A4 集成测试（tests/ 真实进程）
- 症状：三组失败同根——①`serveCellChannel(conn, binding)` 漏传第三参 deps → `deps.tracker` 读 undefined；②`new CompensationExecutor({ledger, factory, onAlert})` 把 opts（onAlert）塞进 deps（第一参）→ 告警缝永不触发；③补偿执行器在**模块顶层**构造，捕获的 `ledger` 尚是 beforeAll 前的 undefined → sweep 一调即 TypeError（被调度器吞成 false → RUN_FAILED，表象远离病灶）

## 规则

1. **多参构造/工厂函数，先读签名再接线**——deps（依赖组件）与 opts（行为选项）是两个参数位；字面量里塞错位置不报错、静默失效。接线后先跑一条"最小正路径"探针确认参数真的到达。
2. **凡依赖 beforeAll 初始化的组件，一律在 beforeAll 内构造**；模块顶层 `const x = new X(deps)` 捕获的是 import 时刻的 undefined。jest/vitest 的 hook 时序不会拯救模块初始化序。
3. **失败表象远离病灶时的定位法**：错误被中间层吞掉（boolean 化、catch 化）时，直接 dump 账本/事件流看"哪个事件没发生"，从缺失事件倒推第一个断点——比读调用栈快。
4. **跨包 import 走 dist**：`tests/` 里 `import {x} from "@keel/foo"` 解析到 `packages/foo/dist`，改完 `src/` 不重新 build 就得到 `x is not a function`（或导出面为空）——先 `pnpm build`（或 `pnpm --filter <pkg> build`）再判"代码写错了"。包 `exports` 指向 dist 是设计（发布面 = 构建产物），不是坑位可改。
