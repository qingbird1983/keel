# P-020 模型按名注册：跨装配重绑 ≠ 重复注册

## 现象

Phase 4 切片③接入 `ModelGateway.registerModel` 后，`tests/profile-assembly-e2e.test.ts` 的
D1-b 红：`SCHED/MANIFEST-INVALID: model is registered twice`。同一个测试文件里先用同一份
`profile.yaml` 装配了一次（D1-a），第二次装配（D1-b）就炸——两次装配的模块与清单完全相同。

## 根因

注册表以**模型名**为键，且是宿主进程级（一份 `ModelGateway` 服务多个 run）。实现时把两件事
混成一条判断：

1. **一份 profile 内同名模型** = 真配置错误（engine 只按名字调用，上游不可判定）；
2. **同一宿主进程里再次装配**（测试复用 runtime、将来多 run 共享宿主）= 合法重绑。

第一次实现只做了"表里已有 → 抛错"，于是第 2 种情况被当成第 1 种拒绝。

## 修复

- `loadProfile` 在装配前按插件集合检查模型名唯一性（同 profile 同名 = 整份拒绝，`stage:"cross-check"`）。
- `ModelGateway.registerModel(reg, {replace?: boolean})`：缺省仍拒重复；`assembleProfile` 显式传
  `replace:true`——"这次装配是这份 run 的权威上游"，避免上一次装配的模块残留。
- 测试只改了行为来源（重绑），断言面没放宽：profile 内同名仍有负路径可加。

## 预防

- 进程级注册表要先写清**唯一性作用域**：是"一份清单内"还是"整个宿主进程内"；两个作用域
  对应两种错误，不能共用一条判断。
- 测试复用 runtime 是好事——它把"多次装配"这种真实宿主形态提前暴露；别用"每次新建 gateway"
  把问题藏起来。
- 审计点：`packages/host/src/profile/assemble.ts` 的模型名唯一性检查 + `registerModel` 的 `replace` 语义。

## 证据

`tests/profile-assembly-e2e.test.ts` D1-b：修复前 `model is registered twice`，修复后 5/5 绿；
`tests/model-kind-e2e.test.ts` 同进程多次装配亦绿。
