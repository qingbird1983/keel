# H-030-运行上下文重构计划与安全取舍

- 日期：2026-11-03
- 范围：切片③之后的 Cordis 调查与重构计划；**本轮零实现代码**

## 本轮做了什么

1. **所有者要求**：先详细调查 Cordis 的运行机制，留下好的、改进不好的，设计一个“类似 Cordis、但专为 Agent 运行基座而生”的底座；同时评估遗漏、把握安全的分寸（Rust 类比），先不实现代码。
2. **Cordis 源码调查**（Context / Fiber / Service / Events）：
   - 值得留下：Context 服务树 + 显式 `inject` + 父链 `locate` + isolate；Fiber 状态机与依赖重载；effect 逆序清理栈；事件 `emit/parallel/serial/bail/waterfall`；Host 层热替换。
   - 不能照搬：Cordis effect 是进程内资源清理（RAII），不是外部副作用补偿；没有 run/session、授权、预算、持久账本、进程隔离。
3. **漏洞复盘（切片③的真实缺口）**：AOP 声明 ≠ 真实 IO；`fs.remove` 无“本次新建”凭证；guard 只查参数；路径是字面 glob，挡不住 `..`/符号链接；多 effect 未发生也补偿；retry 每次新 effectId。
4. **07 稿**（[链接](../../docs/design/phase-3/07-runtime-context-refactor.md)，评审中）：
   - 两层 Context（Host / Run 冻结）+ 能力句柄 + 资源/业务双 effect 栈。
   - `EffectReceipt`：`created/existed/overwritten/identity` 等；只有 `created:true` 且 identity 匹配才允许 builtin 补偿；覆盖写不走 builtin。
   - `workspace.create` 用 `O_EXCL`；删除前 realpath + identity 复核；拒绝 `..`/符号链接/越界/设备文件；多 effect 只补偿有 receipt 的；`toolCallId` 去重。
   - 生命周期 `setup/ready/dispose`；Run 期冻结。
   - 绿/黄/红/黑信任分层；Rust 类比 = 照抄**分层**不是严格度：安全路径最短、风险按比例加摩擦、校验绑真实 IO、逃生口显式可审计。
   - 包改动：新增 `@keel/runtime-context`；core `ContextManager` 拆为 `ToolCatalog` + `PageStore`；cell-runtime/host 收紧；cordis-adapter 不动。
   - R1~R6：决策/ADR → Context 骨架（行为零变化）→ 收据与 Workspace（P0）→ 生命周期/事务/幂等 → 隔离与信任 → 恢复插件 B/C；估 8~14 个专注会话。
5. **文档收尾**：docs/README 登记 07（评审中）并修正 06 的 24 行口径；phase-3 合同与 00-roadmap 加“评审中、切片编号不变”注记；CHANGELOG 0.1.046；CONTEXT 重写；本 handoff；删除最老 H-025。
