- 日期：2026-11-03
- 范围：Phase 2 切片①施工（02 稿 §11 清单一次跑完）——内核/宿主的运行期注册通道、承接层端口与 Cell 入口、A 档合成样本组、四份验收测试、A1 复跑

## 本轮做了什么

1. **注册通道（内核两个新 op）**：`cell-runtime` 的 `CellClient` 加 `registerTool/removeTool`，`CellHandle` 加 `removeTool/getTool/client`；`host/cell-server` 加 `tool.register`/`tool.remove` 两个 case——**先裁决后写状态**（`auth.check` 不过即 `AUTH/DENIED`，两半都不写）、版本号由内核按本 scope 现有条目指派、Cell 提交的版本号与 handler 一律丢弃
2. **能力门禁最小闭环**：新模块 `host/permission-rules.ts`（manifest `permissions` → 授权规则：`tool.provide`→`tool.register/remove`、给了 `allow` 就逐条收窄、`memory.backend` 不产出规则；`tool.invoke` 不推导——那是 Core→Cell 方向）；`supervisor.spawnCell({cellEntry})` per-spawn 换入口，bootstrap 载荷形状不变
3. **承接层（`packages/cordis-adapter` 由 1 文件扩为 6）**：`core.ts` 承接面与 `CORDIS_SURFACE`（mapped/refused/withheld 三张清单，未映射一律抛 `ADAPTER/UNSUPPORTED` 并附改法）、`host-port.ts`（宿主侧施加面，与 Cell 侧同一 `CordisRegistryPort` 异步签名）、`cell-port.ts`（两半提交 + 失败回滚执行表）、`legacy-shape.ts`（三种旧入口形状归一化）、`cell-entry.ts`（旧插件专用 Cell 进程入口，崩溃语义同源）
4. **A 档合成样本 9 枚 + 反例 1 枚**（`tests/fixtures/cordis-plugins/`）：5 常规 + 4 最坏写法探针 + `neg-undeclared`；`tests/fixtures/cordis-rig.ts` 共享 rig（真实子进程 + **断言式 driver** + 激活屏障）
5. **四份验收测试全绿**：`tests/cordis-adapter-tier-a.test.ts`（B1 三主张，9 项）、`tests/cordis-registration-channel.test.ts`（通道语义与 seam，5 项）、`tests/cordis-symbol-scan.test.ts`（零改动五条机械判据，4 项）、`packages/host/test/permission-rules.test.ts`（词表→规则，6 项）；`packages/cordis-adapter/test/*` 三份共 29 项
6. **A1 端口签名统一到异步**（3 处 `await`，主张不变）后**复跑 3 次逐项一致**：`sessions=20 cells=20 rounds=5 events=708` 恒定，仅 elapsed/hostRssDelta 抖动 → B8"Phase 1 主张不退化"这一半成立
7. **施工中撞见的三个真实事实已回写文档**（02 稿 §5.2/§7/§12，只追加不放宽主张）：① 激活就绪时机不在契约里（测试侧用既有信号设屏障，正式时机交切片② 装配链）；② `toolCallTimeoutMs` 拦不住**同步**忙等（能落 timeout 的是异步挂起）；③ scope 分区不按 run 归零 → 跨 run 屏障条目要写 `name@version`
8. 样本目录 `.prettierignore` 长期排除：真样本到位后一次全库格式化会静默毁掉"一行没改"的证据

## 关键决策（评审锚点）

- **激活屏障放在 driver 里而不是 `start` 之前**：run 必须活着经历舱的生死，否则"未报关被拒 → 舱崩 → `RUN_FAILED`"这类负例观察不到
- **屏障只用既有信号**（分区写入 / 一次 `tool.exec` 应答），不新增第三种帧——越出 ADR-0010 授权的协议扩展一律不做
- **反例 rig 的邻居必须自己报关**：策略用 `allow` 收窄出三条注册权，才分得清"被挡下"与"本该如此"；这也是 §5.3 的收窄在真实进程里第一次被跑到
- `tierA-05` 的"耗时"拆成同步忙等与越界挂起两条：合并成一条会把 C-D3 硬强制的真实边界说虚
