# H-016-远端仓库启用与CI首跑拦缺

- 日期：2026-11-02
- 范围：GitHub 私有仓库建立并推送（含三个里程碑标记）→ CI 首跑暴露类型检查缺陷 → 修复并回归

## 本轮做了什么

1. 前置核对：`gh` 已登录（qingbird1983，SSH，repo scope）、无同名仓库、`briefs/` 与 `.env*`/`dist`/`node_modules`/`.zcode` 均在 ignore 内、跟踪内容中无本机绝对路径
2. 建远端并推送：`gh repo create keel --private --source=. --remote=origin --push` + `git push origin --tags`（`phase-0.end` / `phase-1.start` / `phase-1.end` 三个标记全部到远端）；所有者选择**私有**可见性（转公开一键即可，历史与许可证无需改动）
3. CI 首跑（run 41471100770）在 `pnpm typecheck` 步骤失败：`@keel/core` 类型解析不到（host / cordis-adapter / apps.keel 三处 + 一串派生 TS7006 隐式 any）
4. **本地复现**：`pnpm clean` 后 `pnpm typecheck` 同样失败 → 确认非环境差异，而是"类型检查依赖构建产物"的固有缺陷（门禁顺序 typecheck 在 build 之前，干净检出无 dist）
5. 修复：三包类型检查配置加 `paths` 指向兄弟包 `src/index.ts`（build 配置不动，仍走 `exports`→dist）；`apps/keel/tsconfig.json` 的 `include` 补 `test`
6. 回归：从 clean 状态完整跑六道门禁（fmt/lint/typecheck/build/test/check-size）全绿，225 测试；文档与沉淀：CHANGELOG 0.1.020/0.1.021、P-004、CONTEXT 未决与提醒更新

## 验证

- `git ls-remote --tags origin` 三标记齐；`git status` 干净；`gh run list` 可见流水线在跑（本批修复推送后再确认转绿）
- 本地 clean 门禁链退出码 0（`pnpm clean` 起始，非热缓存）

## 关键决策（评审锚点）

- **不改门禁顺序**（standards/04 §1 定稿）：修解析方式而不是把 build 提到 typecheck 前——顺序是规范，解析是缺陷
- **paths 只进 noEmit 配置**：避免"依赖源码被当作构建输入"（rootDir 冲突）同时保住发布面类型来自 `.d.ts`
- **不新增 tag**：`phase-1.end` 指向验收状态（a8b8444），本批修复在其后——里程碑标记不追改
