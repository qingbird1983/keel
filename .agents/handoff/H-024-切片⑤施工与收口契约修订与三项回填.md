# H-024-切片⑤施工与收口契约修订与三项回填

- 日期：2026-11-03
- 范围：Phase 2 切片⑤（锚 **B7②③④⑤ + B8**）——`DECISION.throughSeq`、快照物理持久化、旧 Cell drain 的确定次序、`model.stream` 拉式分片

## 本轮做了什么

1. **红测先行且真红过**（铁律 7）：`tests/snapshot-cross-host.test.ts` 三条真子进程用例，第②条在实现前红在
   `[RECOVER/SNAPSHOT-MISSING] snapshot ref recorded but entry missing`。这条红先于实现存在，才证得了实现满足主张。
2. **B7⑤（throughSeq）**：`Ledger.append(..., { stampSeqBeforeAs })` 在**写队列执行期**盖章（seq 本身就在这里分配，
   调用方先读后写会漏掉读与写之间的直写事件）；`EVENT_SCHEMA_VERSION` 改**按类型**取值（`DECISION`/`MODEL_INVOKED`/
   `MODEL_USAGE` = 2，其余 = 1）。`keel replay` 对新账本打 `throughSeq=N`，对 Phase 1 样例明打"无显式上界"。
3. **B7②（快照落盘）**：`SnapshotStore({rootDir})`，ref 字符串不变、路径另派生（`\|` 是 Windows 非法文件名字符）；
   先内容后引用、tmp+rename+fsync、冷启动扫目录接续版本号；`--snapshots` 缺省由账本根派生同级 `<name>-snapshots`。
   落盘失败的可见性放在**交付入口**（`rt.snapshotFailures` + 非零退出），因为调度器对 `onCheckpoint` 缝的既有语义是尽力而为。
4. **B7③（drain）**：在途集合 + `call()` 统一登记；`halting` 期拒新用既有 `SCHED/BACKPRESSURE`；等待硬界 = 既有
   `toolKillGraceMs`；产物 `DrainOutcome` 是返回值不是事件。`hotSwap` 那条"旧舱由调用方在 run 终态后收"从注释升格为规则 + 断言。
   **副作用**：A3 与 `keel scenario a3` 借 `drainAndReap()` 表达"kill"，新语义让它们的"在途被打断"前提消失 → 把 `kill()`
   转为公开原语，两处改调用，断言一条没改（见 P-010）。
5. **B7④（流式）**：`packages/core/src/stream.ts` 会话表 + 网关 `streamStart/Next/Cancel`；三 op 接线在 `cell-server.ts`，
   舱内客户端三面在 `cell-runtime`；权限随 `model.adapter` 编译出两条动作（词表与报关单零扩展）；承接层 `ctx.llm`
   未知成员改抛 `ADAPTER/UNSUPPORTED` + 去处（护栏，不新增边界表行）。ADR-0013 定形 + 六条实施注记。
6. **基准**：`keel bench` 加 B5a（网关侧首页/全流，含 settle+落账）与 B5b（真舱通道取完同一条流），并加一条
   "量到的东西是不是那条流"的片数核对（不为性能设阈值，但测量本身不能空转）。
7. **修了一处旧缺陷**：`toFrameError` 只对 `ChannelError` 保 `detail`，Core 侧错误跨通道后只剩一个光码（P-009 实例 2）。
8. **文档收口**：契约 01 稿 §3.3/§4.1/§4.5/§4.7/§5/§6/§12 七处注记；ADR-0008 四条 + ADR-0013 六条实施注记（不改决策）；
   Phase 1 报告 §3 限制 2/4 关闭注记 + §5 A8 两行新数据；01 稿 #6 注记（档位未动）；05 手册新增 §9/§10；
   07 稿 §8 打勾 + 新增 §10 七条施工记录；合同 §5 的 B7 勾选；看板与 CHANGELOG 0.1.039。
