# H-018-切片①设计稿承接层骨架

- 日期：2026-11-03
- 范围：Phase 2 切片①设计稿 `docs/design/phase-2/02-adapter-skeleton.md`（草稿，待所有者确认三项）；收尾核对时修掉一处账本真实缺陷（浮空 close）+ CI Node 矩阵 + standards/04 §3 补条

## 本轮做了什么

1. **先核事实再定方案**：对现有代码核对出四条起点事实（02 稿 §2）——F1 Core 可见工具表在正式接线上从未由插件填充（只有测试 rig 手工 `registerTool`，真实 run 的 `tool.discover` 是空表）；F2 适配原型的 `createCordisCtx` 在宿主进程构造，只覆盖可见性一半、无 handler 与执行表；F3 manifest 能力词表进账本但不参与运行期裁决（授权策略手写）；F4 进程后端不拦截 Cell 内原生 `fetch`/`fs`（→ 登记为证据边界，约束 B1/B2 措辞）
2. **seam 定案 D-a**：承接层自带 Cell 入口（`cordis-adapter/dist/cell-entry.js`），宿主以 **per-spawn `cellEntry` 覆盖**换入口，`spawnCell`/bootstrap 形状不变；被否方案四条记录在案（宿主代注册 / cell-runtime 内置旧面 / 双 supervisor / 要求插件静态声明 tools）
3. **注册链路定案**：新增两个 Cell→Core op（`tool.register` / `tool.remove`）；**两半提交次序 = 先 Cell 执行表、后 Core 分区，失败回滚**（Core-first 会留"可见而不可执行"的空壳 = 静默降级）；版本号由 Core 侧指派（Cell 不自算，否则搬回全局注册表）；生效时刻 = 下一轮 `TOOL_SCHEMA_CHANGED`；`@keel/core` 零改动
4. **能力门禁最小闭环**：新模块 `permission-rules.ts`（manifest `permissions` → 授权规则，含 `tool.provide`→`tool.register/remove`、`memory.backend` 不产出规则）；拒绝走 `auth.check` 因此 `AUTH_DENIED` 自动落账 = 留痕可查
5. **同步/异步定案（本片唯一的真实让步）**：Cell 侧 `tools.register/remove/list` 返回 Promise；拒绝"同步返回 + 后台 flush"（版本须自算 + 失败不可见 = 静默降级）。推论：动作属 A 档，**返回值的同步消费属 C 档一行 `await`** → 需回写边界表 #1 补注（待确认第 2 项）
6. **A 档合成样本组设计**：5 常规（toolset / overwrite / dynamic / crash / timer）+ 4 最坏写法探针（require / proto / global / order），每枚探针要求"污染通道结构上不存在"的负向证据；零改动五条机械判据（`.cjs`、源码无 `@keel/` 与 Keel 符号、装载不改写、为过测试改样本即作废、符号必须命中承接面清单）；driver 改为**断言式**（只见可见表、预期工具缺席即失败）以正面解掉 F1
7. 承接面清单 10 行（旧 `ctx` 面 → 本片行为）+ 姿态三条；测试面五份 + A1 端口签名统一（3 处 `await`，复跑 3 次要求）；§10 三项待确认、§11 落地清单、§12 四条限制先登记
8. **收尾核对拦下真实缺陷并修复（先红后修，两个同源口子）**：① `Ledger.rollSegment()` 的 `(await w.opening).close()` 未 await → 关闭时机交给 GC，Node 24+ 判硬错误（开发机 Node 26 偶发命中：226 项断言全过但 `pnpm test` exit=1、`Errors 1 error`；CI 的 Node 22 长期静默）；② 测试 rig 绕过登记器手搓的写入实例从不 close → 同一报错换了出处。生产代码改 `await closing.close()`（失败按 fail-stop 锁存），rig 两处改走"构造即登记 + `afterEach` 统一 close"；新增**环境无关**防回归测试 `packages/core/test/ledger-fd-release.test.ts`（mock `fs/promises.open` 包装每个句柄的 close，断言 checkpoint resolve 时旧段已真正关闭；实证：改回浮空写法必红）；CI 改 Node `[22, 26]` 矩阵；standards/04 §3 补"Promise 型释放必须 await" → [P-005](../pitfalls/P-005-浮空close与Node版本差掩盖硬缺陷.md)

## 关键决策（评审锚点）

- **旧插件的注册必须发生在它自己的舱里**：可见性与可执行性两半由同一次调用打通，否则 B1 的"零改动迁入"只是接口层演示
- **不提供 ≠ 静默成功**：未映射旧面一律抛错给改法去处；`ctx.share.get` 返回 undefined 就是把旧框架的隐式降级搬进来
- **`ADAPTER/*` 只用于"旧面映射缺失"**，运行期裁决失败原样抛 Core 码，归因链必须指向内核
- **能力词表接进运行期裁决**是新写通道 op 的前置：否则等于给不受信进程开一个无裁决的 Core 状态写口（I4）
