# H-021 切片②施工：合成路径、权限收敛与升级接缝落地

- 日期：2026-11-03
- 范围：Phase 2 切片②（锚 B2、B6；`docs/design/phase-2/03-manifest-synthesis.md` §11 清单）

## 本轮做了什么

1. **装载门 + 就绪凭据（ADR-0011 落地）**：`cell-runtime` 的 `startCell` 增 `loadGate`，入口在装载末尾
   `markReady()`；`packages/cordis-adapter/src/cell-entry.ts` 在 `await activate(ctx)` 之后开闸。
   默认入口行为不变（阶段语义、bootstrap 载荷形状、op 集合都没动）。
2. **装配收敛点 `packages/host/src/wire-cell.ts`**：`spawn → serve → alloc → 一次 cell.snapshot 探测`收成一处；
   等不到应答即 `dispose` 该舱并抛 `TRANSPORT/TIMEOUT`（`detail.reason = "CELL_NOT_READY"`），**不新增错误码**。
   `apps/keel/src/runtime.ts` 的 `wireRun` 改走它，`WireRunOptions`/`CellFactory`/`BindRequest`/`HotSwapRequest`
   透传 `cellEntry`（F3 的接缝）。
3. **投影纯函数 `packages/host/src/manifest-synthesis.ts`**：账本事实 → 候选报关单（`AUTH_DENIED` 的 resource
   = allow 名单、`TOOL_SCHEMA_CHANGED` 合并去重、排序保证两次观察字节一致）；越界能力与观察不到的面**一律进缺项**，
   补偿模板永不代造。落地位置与 §7 原写的 `cordis-adapter` 不同，理由记在 03 稿 §12 第 9 条。
4. **两遍观察 `apps/keel/src/observe.ts` + 命令面 `cmd-observe.ts`**：pass 1 空报关单（什么都不放行）→ 候选 v1 →
   pass 2 用 v1 装配并逐个调用工具 → 合并成最终候选 + gaps，落 `<name>.candidate.json` / `<name>.gaps.md`，
   退出码 = 候选能否过五步校验。`main.ts` 的 USAGE 加一行。
5. **权限收敛接进正式接线（F2）**：`buildRuntime` 收 `policy` 选项，`runPolicy(manifest, subject)` =
   `manifestAuthRules` + 宿主自身的 `tool.invoke`/`model.invoke` 放行；`keel run` 走报关单策略，
   写死的演示表 `p1` 退为 scenario/benchmark 的显式选项。
6. **测试面**：`packages/cell-runtime/test/ready-gate.test.ts`(5)、`packages/host/test/wire-cell.test.ts`(7)、
   `packages/host/test/manifest-synthesis.test.ts`(9)、`tests/cordis-manifest-synthesis.test.ts`(3，B2)、
   `tests/cordis-legacy-upgrade.test.ts`(2，B6)、`apps/keel/test/cli.test.ts` 加 `observe` 冒烟(1)；
   B 档样本 5 枚（`tierB-01/02/03/04-v1/04-v2`）纳入 `cordis-symbol-scan` 的零改动机械判据。
7. **文档**：03 稿状态转"施工完成"、§11 打勾、§12 追加第 6~9 条限制、§8 补实际体量、§9 改写 rig 屏障那条；
   看板 Phase 2 行改"切片②已完成"；CHANGELOG 0.1.030。

8. **门禁随机红的源头修掉**：11 个测试文件各自 `execSync("pnpm build")`，41 个 worker 并发抢 `dist/` 里的
   同名产物 → `pnpm clean` 起全链时一个文件拿到 `ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL`。构建挪进
   `tests/fixtures/global-setup.ts`（vitest globalSetup，主进程串行一次），测试文件里的构建调用全部删除
   → [P-002 规则 5](../pitfalls/P-002-集成测试装配接线四类错.md)。

## 验证

- 全库 `pnpm test`（从 `pnpm clean` 起）：**41 文件 / 311 测试全绿**（含第一阶段契约级五测试点、A1 规模项、切片① B1 组 = B8 复跑）
- B2 三条硬线：① 不放行也读得到调用面（3 笔 `AUTH_DENIED`、无 `TOOL_INVOKE`、终态 `failed`）；
  ② allow 恰好等于观察到的名字集且候选过五步校验、三个工具真被驱动执行；③ 上界外当场拒（`bonus`），
  补进上界后同一次调用才成立。
- B6 两条：无 `migration` 的旧插件原子换绑（`replacesVersion` 留痕、`flip@2` + `extra@1` 可见）且**换绑后 run 真跑**；
  声明 `migration` 的旧插件在首个 `cell.migrate` 拿 `CELL/MIGRATION-MISSING` 当场回退，绑定表停在 1.0.0，
  被丢弃的新舱只留下一条"多声明被拒"，旧舱 run 照跑。
- 六道门禁从 `pnpm clean` 起全链绿：format / lint / typecheck / build / test / check-size 全部 0 退出
- **CI 首轮（Node 22 + 26）红在 B6②，本机 Windows 却是绿的**：那个被丢弃的新舱里并存两条失败——多声明的工具被旧策略拒
  （→ 未决拒绝 → 舱崩 → 通道断）与迁移钩缺失（→ migrate 报错），谁先到达随平台不同。修法是把权限面给到两版名字的上界，
  让失败路径唯一，断言改成账本无痕迹 + 分区留下未回收的注册 → [P-006 第 4 条预防](../pitfalls/P-006-真实子进程测试的时序屏障.md)
