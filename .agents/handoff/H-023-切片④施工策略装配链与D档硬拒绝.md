- 日期：2026-11-03

## 本轮做了什么

1. **策略舱的进程体**（`packages/cell-runtime`）：`policy-main.ts` 入口只认 `export const hooks`，不注入 `CellClient`；
   `policy-hooks.ts` 的 `normalizePolicyHooks` 把"导出集合 = 报关声明集合"钉在装载期（少 = 两张皮，多 = 未申领插话）；
   `cell.ts` 新增 `policy.hook` 路由（载荷 `{hook, input}`，不设舱内时限）与 `setHooks`。
2. **宿主接线**（`packages/host/src/policy-link.ts`）：预检（kind / 白名单 / 抢注整份拒）→ 全部起舱并探就绪 →
   **最后一步整批注册**。失败 = 整批 drain 后原样重抛，总线上不留半挂的 handler。
3. **交付入口**（`apps/keel`）：`BuildRuntimeOptions.policies` + `keel run --policy-manifest/--policy-module`（成对可重复）；
   `ASSEMBLY_RECORDED.policies` 经 `wireRun` 落账（无策略时不写该字段，旧账本形状不变）；`closeRuntime` 收策略舱。
4. **内核只动了两处既有面**：`HOOK_TIMEOUT_MS` 导出为唯一时限来源；`AssemblyRecordedPayload` 追加 `policies?`。零新错误码。
5. **样本**：策略模块 7 枚（四 hook 各一 + 违规响应 + 装载期负样本 + CLI 配对用）在 `tests/fixtures/policies/`；
   旧形状 D 档尝试 3 枚 + B7① 工具集 1 枚在 `tests/fixtures/cordis-plugins/`；畸形 manifest 2 枚进
   `fixtures/manifest-negative/`（组内 6→8 枚，README 与 `assembler.test.ts` 的防漂移清单同步）。
6. **验收测试**：`tests/policy-chain-attribution.test.ts`（B7①，9 条）、`tests/cordis-d-tier.test.ts`（B4，13 条）、
   `packages/host/test/policy-link.test.ts`（13 条）、`packages/cell-runtime/test/policy-cell.test.ts`（10 条）、
   CLI 冒烟 +2（接通 / 抢注整份拒）、符号扫描判据 +1（D 档尝试不引出任何新面）。
7. **文档**：ADR-0012 追加四条**实施注记**（不改决策）；06 稿 §8 打勾 + 新增 §10 施工期记录八条；
   01 稿 #7/#14 补实现期注记；05 手册 §8 从"只给方向"改成可抄路径 + 证据落点表；契约 §4.8 的载荷描述与实现对齐；
   Phase 1 报告 §3 第 3 条与 §9 回填清单标注已兑现；看板与 CHANGELOG 0.1.036。
