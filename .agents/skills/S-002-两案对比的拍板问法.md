# S-002 两案对比的拍板问法

## 适用场景

需要所有者从两个技术上正确、代价不同的方案里选一个，且要留下可追溯的决策记录（ADR + 设计稿 + 合同确认记录）。

## 前置条件

- 两案都已在 ADR 里写成"方案 A / 方案 B"，含对比表、建议、被否理由与重评条件；
- 两案的影响面已经落到设计稿的具体章节（哪一节会被改写）。

## 步骤

1. **ADR 用字母**（方案 A / B）写对比与建议——便于引用与评审。
2. **问所有者时用方案名，不重复字母**：例如"新增一条表面事件"vs"复用预留字段"，而不是"A / B"。若界面必须用字母，字母要跟 ADR 同序，并在选项描述里写清方案名。
3. **回填按方案名记录**：在 ADR 的"决策"节写"选 **新增 `SURFACE_COMPACTED`**（本篇方案 B；选项以名字呈现）"，避免"UI 选了 A、ADR 里却是 B"的错位。
4. **同一轮把依赖段落改成确定口径**：设计稿里所有"若选 A 则……"的句子要么删、要么改成最终事实；合同 §8 的确认记录同步补 K 编号。

## 验证方法

- 让第三个人只看 ADR 的"决策"节与设计稿，能说出最终选了哪个方案，且不会把字母对错。
- 搜一遍"若选 / 待拍板 / 两案"，确认没有残留的分叉叙述。

## 失效条件

- 只有单一方案（无需拍板）；
- 方案本身以字母为正式代号（如 A/B 测试分组），此时字母就是事实，不能用名字替换。
